## 一、判死双信号(防误判的核心)

### 1.1 为什么双确认

| 单信号判死的缺陷 | 后果 |
|---|---|
| 只看实例 lease | 平台 GC 停顿/网络抖动导致"没续上"≠实例真死 → 误判 → **双消费** |
| 只看快照 TTL | 执行器忙到 30s 没写快照 ≠ 卡死 → 误判 → **双消费** |

双信号要求两者**同时**失效,把误判概率压到"实例真死"级别:

```
确认判死(两条件同时满足):
  ① 实例注册键已消失(注册 lease 30s 未续租,etcd 自动删键)
  ② 该分区快照失效(键被删,或键在但 30s 停更,且无 stopped 帧)
```

### 1.2 三个判定依据的物理形态

| 信号 | 键 | 租约 | 粒度 |
|---|---|---|---|
| 实例活性(管理面) | `/dcp/{ns}/instances/{id}` | 注册 lease 30s,**每 ns 一条** | 实例在域内的身份 |
| 分区活性(数据面) | `/dcp/{ns}/tasks/{taskId}/parts/{partId}/snap` | 快照 lease 30s,**每实例一条共享** | 分区级消费活性 |
| 分区归属(事实) | `/dcp/{ns}/tasks/{taskId}/parts/{partId}` | 持久键,无租约 | 分区归谁 |

- 两条活性链独立:注册键被删不会连带删快照键(不同 lease),双信号可以独立消失;
- 快照"失效"两种形态:键被物理删除(快照 lease 过期)/ 键在但 ts 超 30s 停更(上报线程死、续租流活);
- 快照 lease 实例级共享:进程死则全部分区快照一起消失,判死窗口一致;代价是快照流是进程级单点(单独断流 → 全部分区走 stuck 路径迁出,靠保守交接回滚与告警缓解)。

### 1.3 判死判定状态机(judgeDead,分区粒度)

主每 10s 一轮,对每个 ASSIGNED 分区二维判定:

| 实例注册键在吗 | 分区快照状态 | 判定 |
|---|---|---|
| 在 | 新鲜(30s 内有更新) | 正常,不动 |
| 在 | 标记主动停止(stopped 帧) | **exec-stopped**:执行器主动停/FAILED,超宽限期后迁移 |
| 在 | 失效(键没了或停更) | **stuck**:实例活着但快照停更,超 30s 宽限期后迁移 |
| 没了 | 新鲜 | **SUSPECT 观察**:失联但快照仍在更新,不判死(防双消费),告警限流 |
| 没了 | 失效 | **death 判死**:双信号齐灭,开交接 |

旁路裁决(优先级高于上表):

- **钉住锁**:分区被 pin 且锁未过期 → 不回收,等待人工裁决(TTL 到期自动解锁);
- **一次性任务**:重派次数达上限(缺省 3)→ FAILED 终态;执行器上报 done → SUCCEEDED 立即释放槽位(豁免宽限期)。

## 二、交接两模式(openHandoverOrReclaim)

| 维度 | AGGRESSIVE | CONSERVATIVE |
|---|---|---|
| 判死要求 | lease 过期即可 | 注册键消失 + 快照失效双确认 |
| 中间态 | 无(直接回收) | MIGRATING + handover 记录(confirmDeadline = now + 30s) |
| 迁移时延 | ~40s(lease 30s + 决策 10s) | ~70s(判死 30s + 窗口 30s + 决策) |
| 双消费窗口 | 存在(业务幂等吸收) | 无(确认死亡才转移) |
| 适用 | sync(ODKU)/indexer(锚点) | outlet(打标无幂等) |
| 交接态换主 | 无状态可丢 | handover 持久化在归属键,新主读到期续判 |
| 回滚 | 无(无窗口) | 按起因对称回滚(见下) |

```
AGGRESSIVE:
  判死确认 → 直接回收:归属键改「待分配、持有者清空、版本号+1、交接信息清空」
  → 同轮立即再分配,无观察窗口、无回滚

CONSERVATIVE:
  ① 开交接:casPut 归属键改「交接中」,持有者暂不变,写入交接信息(源持有者/确认时限=30s 后/起因)
  ② 窗口内每轮检查:
     - 回滚(证据按起因对称):
        death        → 源实例注册键重新出现(复活)
        stuck/exec-stopped → 源分区快照恢复新鲜(snap==1)
        manual/rebalance → 不回滚(主动迁移无误判)
       → 回滚:casPut 改回「已分配、持有者还给源、清空交接信息」
     - 确认:确认时限到期 或 源主动停(stopped 快照,快通道提前确认)
       → 回收:改成「待分配、持有者清空」
```

**为什么设 confirmDeadline 兜底**:交接窗口内若再次换主,新主读 handover 记录继续判定——但判定需要一个"最迟收口时间",否则交接态可能永久悬挂;deadline 到期即视为确认(此时即便源复活,也要先完成迁移,源侧的线程由其 watch 到归属变更后自停)。

## 三、判死迁移完整时序(实例 A 死亡,保守模式,单分区)

| 时刻 | etcd 侧 | 主侧动作 |
|---|---|---|
| t0 | A 宕机,注册/快照两条 keepAlive 流停 | 无感 |
| t0~t30 | 两个 lease 各自倒计时 | 无感 |
| t30 | 注册键被删(A 从存活列表消失);快照键被删(快照失效) | 无感 |
| t40 | 下一轮决策 | 判定:失联 + 快照失效 → **death 判死** |
| t40 | | casPut:归属键改「交接中」,确认时限=t40+30s |
| t40~t70 | 窗口内每轮检查 | 源复活?否;主动停快照?否 → 等待 |
| t70 | 窗口到期 | casPut:回收为「待分配、持有者清空、版本号+1」 |
| t70 | 同轮补分配 | 打分 → casPut:持有者=B、已分配、记录分配时刻 |
| t70+ | B 监听到归属变化 | 对账 → 启动执行器 → B 从提交位点续消费 |

**SUSPECT 分支**(A 的注册流断但快照流还活着):t30 注册键被删、快照键还在更新 → 主每轮看到「失联但快照新鲜」→ 观察不判死 → 快照也停更后(双信号齐灭)才进入上面 t40 的判死——**判死整体推迟到双信号都灭**。

**回滚分支**(窗口内源复活):death 起因下源注册键重新出现 → 每轮检查发现 → casPut 改回「已分配、持有者还给源」→ 零迁移。stuck/exec-stopped 起因下源快照恢复新鲜(snap==1)→ 同样回滚。

## 四、迁移后半程(判死后到新实例接手)

```
① 归属键回收:待分配、持有者清空、版本号+1
② 主同轮/下轮分配:打分选中实例 B
   → casPut:持有者=B、已分配、版本号+1、记录分配时刻
③ B 的 watch 收到归属键变更事件 → 触发对账
④ 对账实读 etcd 确认持有者是自己 → 启动执行器 → 消费线程启动
⑤ 旧的源实例若复活:对账发现归属易主 → 自停执行器(并写「主动停止」快照)
```

所有归属键改写全部走 **casPut(核对读时内容一致才写)**——并发安全,任何时刻只有一个写者成功;epoch 每跳 +1。

## 六、故障处置全表

| 故障 | 检测(时延) | 处置 | 恢复后行为 | 影响 |
|---|---|---|---|---|
| 实例宕机 | 注册键消失(30s) | 判死(按模式)→ 分区迁移 | 复活后重新注册,按剩余归属对账 | 分区中断 ~40s(激进)/~70s(保守) |
| 执行器卡死 | 快照失效(30s) | 活性告警 → 按模式迁移该分区 | 实例不重启的话,该分区在别处跑 | 单分区中断 ~1min |
| 快照流单点故障 | 快照键全消失 | 全部分区走 stuck 路径迁出(保守交接可回滚) | 快照恢复则窗口内回滚;否则迁空后实例空转,进程重启重新入池 | 实例级分区批量迁移,告警可见 |
| 主宕机 | leader lease(30s) | 竞选换主 → 全量读恢复 | 旧主复活=普通实例(角色降级) | 决策停顿 10s 级 |
| 交接窗口内换主 | — | 新主读 handover → deadline 续判 | 交接不中断不重做 | 零影响 |
| etcd 不可用 | 写失败/watch 断开 | **执行器继续跑**(归属冻结),主暂停决策 | 恢复后:主重读、实例重连 watch,对账收敛 | 有吞吐无调度 |
| 网络分区(主侧) | lease 续不上 | 旧主退位,新主当选;旧主写因 CAS 失效 | 分区恢复后旧主发现已降级 | 短暂决策停顿 |
| 网络分区(实例侧) | lease 过期 | 按实例宕机处置(分区迁移) | 网络恢复后实例对账,发现自己不再持有 | 可能短时双消费窗口(保守模式无) |
| 缩容追平超时 | deadline(10min) | 告警 + 人工介入 | 人工决定继续等待或回滚路由 | 待缩分区悬置 |

## 七、etcd 故障的精确行为(保守策略)

```
检测:etcd 写失败(带重试退避)或 watch 流断开
主:   停止一切"改归属"类决策(分配/迁移/缩容推进);保留检测与日志
实例: 执行器线程继续跑(已 start 的不停);lease 续租/快照续写继续尝试(缓冲本地)
      对账 diff 冻结(不 stop 不 start——没有新的归属事实)
恢复: 主重连 → 全量读 → 决策恢复;实例重连 watch(带 revision 续传,不漏事件)
      → 对账 diff 重算 → 收敛到 etcd 最终态
不变式:任何时刻执行器只由"当前归属键"驱动;etcd 不可用期间归属键不变,故执行器安全。
```

**为什么不是"etcd 不可用就全停"**:消费链路的可用性依赖归属键的稳定性而非 etcd 的实时性;冻结决策即可保证"不双消费 + 不丢吞吐",全停反而把 etcd 的故障放大成整个数据面的故障。

## 八、脑裂防护(双层)

```
第一层(主层):leader lease 决定唯一主——旧主 lease 续不上自动退位,
  即便旧主不自知(网络分区),它的所有写事务都带 epoch 条件,
  新主已写入的键 epoch 已变,旧主写必然 CAS 失败。
第二层(执行层):实例启动执行器前检查"归属键 owner 是否仍是我"(start 前断言),
  归属已改则拒绝起线程——防御"实例与主之间网络分区,实例自以为仍持有"。
```

## 九、与存量控制面的差异点

| 场景 | 原控制面 | 框架 |
|---|---|---|
| 单元失联 | 租约过期 → 释放 + **告警人工处理** | 双信号判死 → **自动迁移** |
| 停滞检测 | 5min 才告警 | 30s TTL 检测 + 自动迁移 |
| 主故障 | 单点(无选主) | 每 ns 独立选主,秒级恢复 |
| 下发通道 | 推模式(dispatcher) | 拉模式(watch 对账),断连自愈 |
| 交接状态 | 主内存(重启即丢) | 持久化在归属记录,换主可续 |
