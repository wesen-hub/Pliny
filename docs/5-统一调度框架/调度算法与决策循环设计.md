# 调度算法与决策循环设计

> 承接总纲 §六。细节级:打分伪代码、CAS 事务条件、再平衡算法、epoch 实现。状态:初版,随讨论迭代。

## 一、决策循环(主循环伪代码)

```
调度主启动:
  lease campaign 当选后,全量读本 ns:
    instances[] / tasks[](spec+status+parts) / rules / ops[]
  watch 四个前缀(事件驱动加速,1s 节流合并):tasks / instances / ops / leader
  然后进入循环:

loop(每 10s 一轮;watch 事件到达时立即触发一轮,节流合并):
  ① ensureTasks     任务生命周期:SUBMITTED→补 PENDING→RUNNING;DRAINING/GONE→回收分区
  ② expirePins      TTL 锁到期 → CAS 清 pin,分区回到自动管理
  ③ consumeOps      手动指令:钉/解/定向迁移(锁,详见子文档⑧)
  ④ detectDeath     判死:注册键消失 → 交接;快照停滞 → SUSPECT
  ⑤ handoverProgress 推进 MIGRATING 中间态(双窗口到期/stopped 快照/源复活回滚)
  ⑥ allocatePending 补全分配(尊重锁的定向分配:PENDING 且 pin → 只给 pinnedTo)
  ⑦ rebalance       负载再平衡(阈值+防抖+步进;跳过锁分区)
  ⑧ autoscale       扩缩容规则(水位+持续周期+冷却+步长,见扩缩容子文档)
```

**触发时机 = 周期 tick 兑底 + 事件驱动加速**:周期循环是正确性底线(漏任何事件 10s 后必收敛);事件驱动把关键场景降到秒级:

| 事件 | watch 前缀 | 立即触发的环节 |
|---|---|---|
| 任务提交/变更 | tasks/spec | ①→⑥ |
| 任务下线 | tasks/status | ① |
| 实例上线 | instances | ⑥(新候选,有 PENDING 即接单) |
| 实例下线(租约过期) | instances | ④(不依赖 tick) |
| 运维钉/解/迁移 | ops | ②→③→⑤ |
| leader 键删除 | leader | 重新竞选 |
| 运行中负载失衡/rps 超水位 | 周期扫 snap | ⑦/⑧ |

**关键约束**:主的一切决策结果都先落 etcd 再生效;循环内任何一步异常(如 etcd 瞬时不可用)只跳过本轮,不中断循环、不清空内存态(内存态仅作缓存,以 etcd 为准)。

## 二、打分公式(实例选择)

```
score(i) = α · (1 − cpu_i/100)              // 机器余量(meta 10s 刷新)
         + β · (1 − assigned_i/capacity_i)  // 槽位余量
         + γ · affinity(i, part)            // 亲和:part 原归属==i ? 1 : 0
         + δ · weight_i                     // 人工权重(0.5~2.0,默认 1.0)

缺省系数:α=0.4 β=0.3 γ=0.2 δ=0.1(可配)
候选过滤(不满足直接淘汰,不参与打分):
  · status == ONLINE
  · paused == false
  · assigned_i < capacity_i
  · 迁移目标时:目标 ≠ 当前 owner(除非当前 owner 已失联)
```

设计意图:

- **亲和项**让"原地不动"天然胜出——分配时新分区无原归属(affinity=0),迁移时原归属实例有 +0.2 优势,抑制无谓迁移;
- **槽位余量**保证容量硬约束内均匀摊派(而非只看机器指标);
- 机器指标只取瞬时 meta,用于差异化(两台槽位相同的实例,选负载低的那台)。

## 三、CAS 事务的精确条件(etcd txn)

分配一个分区 P 给实例 I 的写事务:

```
Txn(P 的归属键):
  IF  P.state == PENDING            // 条件 1:未被并发分配
      AND P.epoch == myReadEpoch    // 条件 2:读到后未被他人改过
  THEN
      put P = { owner: I, state: ASSIGNED, epoch: P.epoch + 1 }
  ELSE
      abort(下一轮重试)
```

迁移一个分区 P(从 A 到 B)的写事务:

```
Txn(P 的归属键):
  IF  P.state == ASSIGNED AND P.owner == A AND P.epoch == myReadEpoch
      AND (handover 语义满足:AGGRESSIVE 无附加条件;
           CONSERVATIVE:A 的 lease 已过期 AND A 的快照 TTL 已失效)
  THEN
      put P = { owner: B, state: ASSIGNED, epoch: P.epoch + 1 }
  ELSE abort
```

保守交接分两阶段写(中间态持久化):

```
阶段一(标记交接):
  IF P.state == ASSIGNED AND P.owner == A AND P.epoch == e
  THEN put P = { owner: A, state: MIGRATING, epoch: e+1,
                 handover: { sourceOwner: A, confirmDeadline: now+60s } }
阶段二(完成转移):
  IF P.state == MIGRATING AND P.handover.sourceOwner == A
     AND (A 失联确认 OR confirmDeadline 到期)
  THEN put P = { owner: B, state: ASSIGNED, epoch: e+2, handover: null }
```

**epoch 的意义**:每一跳变更 +1;写入方必须带"读时 epoch"作条件,不匹配即放弃——双主窗口、旧主迟到写、并发决策全部被 CAS 拒之门外。

## 四、再平衡算法

### 4.1 触发条件(任一)

| 触发 | 条件 |
|---|---|
| 新实例入池 | 实例注册 ONLINE(首次出现) |
| 实例下架 | 后台发起 DRAINING(§运维后台) |
| 失衡 | 量化条件见下(带持续期防抖) |
| 人工 | 后台"一键均衡" |

**失衡量化条件(AND,需同时满足)**:

```
最忙实例槽位占用率 > 0.8
AND 最忙/最闲槽位占用率差 > 0.3(或打分差 > 0.3)
AND 持续 ≥ 3 个决策周期(30s 量级,防瞬时抖动)
```

再平衡解决**稳态失衡**(长期负载不均),判死解决**故障接管**(死了必须立即动);故障接管永远优先,再平衡只在系统健康时进行。

### 4.2 选迁移对(贪心,每轮限量)

```
选对原则:目标 = 对分区打分最高的实例;源 = 槽位/负载超标的实例;跳过锁分区(子文档⑧)
步骤:
  ① 计算各实例负载指标 loadIndex_i = assigned_i/capacity_i 与吞吐占比
  ② 找出超载实例集合 Over = { loadIndex > 均值×(1+θ) 或 cpu>80 }
  ③ 对 Over 中每个实例,取其打分最低的分区(迁移代价最小者:affinity 低、吞吐低)
  ④ 目标 = 该分区在"非 Over 实例"中打分最高者
      (迁移前校验:目标存活、未暂停、槽位未满、快照新鲜)
  ⑤ 限量:单轮迁移 ≤ 1 个分区/ns(步进:迁完等下一轮再评估)
```

### 4.3 防抖动

- 触发条件本身带持续期(失衡要持续 3 周期);
- 全局冷却:任意再平衡后 10min 内不再触发同类再平衡;
- 分区级冷却:被迁移的分区 10min 内不再被迁移(防双主/反复踢皮球);
- 目标实例冷却:刚接过分区的实例,短期内不从中迁出。

## 五、分配与实例对账的分工

| 职责 | 主(决策循环) | 实例骨架(对账) |
|---|---|---|
| 归属写 | ✅ CAS 写 | ❌ 只读 |
| 归属 → 线程 | ❌ 不通知 | ✅ watch diff → start/stop |
| 执行器装载 | ❌ | ✅ lookup(handlerRef)→ newExecutor |
| 执行器失败上报 | 读结果(FAILED 状态) | ✅ 装载失败写事件 |

**为什么"主不通知、实例自己 diff"**:主的通知(推模式)在换主时必然断连重连;而归属键是唯一事实源,实例对账天然幂等、天然可恢复。主与实例之间唯一的"协议"就是归属键的最终态。

## 六、边界与退化行为

| 场景 | 行为 |
|---|---|
| 无候选实例(全部满载/暂停/下架) | 分区留 PENDING,决策循环每轮重试;告警"无可用实例" |
| CAS 冲突(并发/双主窗口) | 放弃本轮,下轮重读重试(最多 3 轮后告警) |
| 决策循环卡死(主假死) | leader lease 无法续租 → 其他实例竞选接管(业务层无感) |
| 实例短暂重启(TTL 内) | 归属不变,实例按 etcd 恢复线程,不进入分配流程 |
| 新实例注册但 lease 未稳 | 观察 1 个周期(10s)确认稳定后再纳入候选 |
