# 生命周期与状态机设计

> 承接总纲 §七。细节级:任务/分区/实例三张状态机、八阶段精确动作、三重启场景。状态:初版,随讨论迭代。

## 一、三张状态机

### 1.1 任务状态机(任务级,status 键,主推进)

```
SUBMITTED ──(分配开始/首个分区 ASSIGNED)──▶ RUNNING
    │                                          │
    │            (业务外壳删 spec / 后台注销)    │
    │                                          ▼
    └─────────────────────────────────────▶ DRAINING
                                               │ (所有分区清理完毕)
                                               ▼
                                             GONE(清理记录)
转移规则:
  · SUBMITTED:spec 已写,parts 全 PENDING;
  · RUNNING:至少一个分区 ASSIGNED(部分 PENDING 属正常,扩缩中);
  · DRAINING:不再接受新分区,已有分区逐一切 DELETING,追平后清;
  · GONE:全部 parts 清理,spec/status 删除,任务生命周期结束。
```

### 1.2 分区状态机(分区级,parts 键,主 CAS 推进)

```
                    ┌──────────────(实例失联判死 / 迁移)─────────────┐
                    │                                               │
 PENDING ──分配──▶ ASSIGNED ──保守交接──▶ MIGRATING ──双确认完成──▶ ASSIGNED(新 owner)
    ▲                │
    │                ├──(缩容/注销)──▶ DELETING ──(lag 归零)──▶ 清记录
    │                │
    └──(新分区:扩分区后 spec 更新)─────────────┘

各状态下的 actor:
  PENDING    : 主(分配)、实例(不动作)
  ASSIGNED   : owner 实例起线程跑;主监控活性
  MIGRATING  : 源实例停线程、目标实例待命;主确认双窗口(保守)或直接完成(激进)
  DELETING   : owner 实例线程仍在跑(追平);主判 lag 归零后清记录
```

### 1.3 实例状态机(每 ns 维度独立演进,实例+该 ns 主共同推进)

```
(每 ns 注册视角,同一实例在不同 ns 的状态相互独立)
        启动注册(全局身份+逐 ns 注册)     后台下架指令(本 ns)
 (无) ───────────────────────▶ ONLINE ───────────────────▶ DRAINING
                                  │                              │
                            本 ns lease 过期              (本 ns 分区迁空) 人工关机
                                  ▼                              ▼
                               SUSPECT ──────(恢复续租)──▶ ONLINE
                                  │
                                  ▼ (判死完成,本 ns 归属全部改 PENDING)
                               OFFLINE(清理本 ns 注册;其他 ns 不受影响)
转移规则:
  · DRAINING:本 ns 内不接新分区,主逐步把其分区迁出(触发再平衡);不影响其他 ns;
  · SUSPECT:本 ns lease 过期未确认死,分区进入判死流程(保守:双窗口;激进:改 PENDING);
  · SUSPECT 期间若实例恢复续租 → 回 ONLINE,归属尽量保持(亲和项天然倾向原地);
  · 实例进程整体崩溃 → 所有归属 ns 的 lease 各自过期、各自判死迁移(并行互不影响)。
```

### 1.4 实例接入集群流程(声明 namespace 与多 ns 归属)

**声明方式:启动参数(部署属性)**

```
./scheduler-instance \
  --id=inst-01 --addr=10.0.8.17 \
  --namespaces=sync,indexer \\      # 归属的 ns 列表(可多)
  --cap.sync=64 --cap.indexer=32 \\ # 每 ns 独立槽位(本 ns 内最大线程数)
  --campaign=sync                  # 可选:参选哪些 ns 的主(默认全部)
```

**注册模型:全局身份一份 + 每 ns 调度注册一份**

```
/dcp/instances/{id}        全局身份:addr/namespaces/meta(机器指标,进程级) + lease
/dcp/{ns}/instances/{id}   每归属 ns 一份:capacity/weight/paused/status + 独立 lease
```

**完整接入流程**

```
① 启动读参:id/addr/namespaces/每 ns capacity/参选配置
② 自检:对每个归属 ns,校验该 ns 所需执行器可装载(spi jar 是否带齐)
③ 全局注册:/dcp/instances/{id} + lease
④ 逐 ns 注册:对每个归属 ns:
     写 /dcp/{ns}/instances/{id}(capacity/weight/ONLINE) + 独立 lease
     watch 本实例在该 ns 的归属键
     按配置候选竞选 /dcp/{ns}/leader(可同时当选多个 ns 的主)
⑤ 稳态循环(10s):
     续各 ns lease + 刷新全局 meta
     对账 diff 按 ns 分组:归属=我 → start(ctx);迁走 → stop()
     若当选某 ns 主 → 跑该 ns 决策循环
⑥ 退出:
   优雅退出:逐 ns 置 DRAINING/注销 → 停执行器 → 释放 lease
   崩溃退出:所有 ns lease 自然过期 → 各 ns 主独立判死迁移
```

**多 ns 归属的关键语义**

| 维度 | 语义 |
|---|---|
| 槽位分账 | 每 ns 独立 capacity,打分只用本 ns 注册键;总线程数 = Σ 各 ns capacity,部署配置人工把关(防机器超载) |
| 执行器隔离 | 同进程内不同 ns 的执行器互不感知(执行器只拿 ctx,不知道 ns) |
| 判死 | 每 ns 独立 lease 独立判死;进程崩溃 → 各 ns 并行迁移 |
| 竞选 | 可按 ns 配置是否参选;可同时当选多 ns 主 |
| 下架/暂停 | 按 ns 维度操作,不影响其他 ns 运行 |
| ns 隔离 | 调度主仍只 watch 本 ns 前缀,多 ns 归属不破坏隔离 |

## 二、八阶段精确动作

| 阶段 | 参与者 | 精确动作 |
|---|---|---|
| ① 框架启动 | 实例 | 注册 instances/{id}(lease 30s,10s 续租)→ watch 本 ns → 候选竞选主;当选者全量读恢复决策上下文,进入循环 |
| ② 任务创建 | 业务外壳 | 校验执行器可装载 → 写 spec + status=SUBMITTED + N 条 PENDING(事务性写入) |
| ③ 调度决策 | 主 | 决策循环扫 PENDING → 候选过滤+打分 → CAS 写归属 ASSIGNED(详见调度算法子文档) |
| ④ 执行 | 实例+执行器 | 对账 diff:新增→装载执行器→start(ctx);执行器 poll→业务→提交→计数;10s 续快照 |
| ⑤ 稳态监控 | 主/监控组件 | 读快照+Kafka endOffset → 派生指标 → 聚合 → 告警巡检(详见监控子文档) |
| ⑥ 自动扩缩容 | 主+外壳+实例 | 水位判定 → 扩容(建议→外壳扩分区→新 PENDING)/缩容(钩子→追平→DELETING)(详见扩缩容子文档) |
| ⑦ 故障迁移 | 主 | 实例 lease 过期 → 判死(按交接模式)→ 改归属 → 新实例对账起线程 |
| ⑧ 任务注销 | 外壳+主+实例 | 删 spec → DRAINING → 分区 DELETING → 追平 → 清记录 → GONE → 外壳释放资源 |

## 三、三条关键时序

### 3.1 创建 → 跑起来(乐观路径)

```
外壳          etcd              主              实例           执行器
 │──写spec+PENDING→│              │               │              │
 │             │◀─决策循环扫描────│               │              │
 │             │◀──CAS ASSIGNED──│               │              │
 │             │──watch 事件──────────────────────▶│              │
 │             │              │               │─diff 新增→装载─▶│
 │             │              │               │──start(ctx)────▶│ poll→业务→提交
 │◀─(可选)watch status────────│               │              │
```

### 3.2 故障迁移(保守交接)

```
主                          etcd                    实例B           执行器B
 │─发现 A lease 过期─────────▶│                       │               │
 │─阶段一:MIGRATING+handover─▶│                       │               │
 │─双窗口确认(lease+快照)─────▶│                       │               │
 │─阶段二:owner=B,ASSIGNED───▶│──watch────────────────▶│─diff 新增────▶│ start
```

### 3.3 注销(带追平)

```
外壳        主                    etcd                   实例         执行器
 │─删spec───▶│                     │                      │             │
 │           │─status=DRAINING────▶│                      │             │
 │           │─parts 全 DELETING──▶│                      │             │
 │           │                     │─watch────────────────▶│(线程继续跑追平)│
 │           │─判 lag 归零────────▶│                      │             │
 │           │─清 parts─status=GONE▶│                     │             │
 │           │                     │─watch────────────────▶│─stop───────▶│
 │◀─watch GONE(释放业务资源)─│                     │             │
```

## 四、三种重启场景的精确行为

### 4.1 实例 30s TTL 内重启(最常见)

```
前提:进程崩溃/被杀,lease 未过期(30s 窗口内重新注册成功)
行为:
  · 归属记录原样保留(主未察觉任何变化,不触发判死/重分配);
  · 实例重启后:注册(同 id)→ watch → 对账 diff 发现归属=我的分区 → 重新装载执行器起线程;
  · 消费起点:执行器按自身语义恢复(消费组位点续 / bizMeta 起点 seek)。
代价:实例中断 < TTL 的分区空窗;换取"零无谓迁移"。
```

### 4.2 调度主重启(换主)

```
前提:leader lease 过期(主挂/假死/网络分区)
行为:
  · 其他实例 watch 到 leader 键过期 → 竞选 → 新主当选;
  · 新主全量读本 ns(instances/tasks/parts/rules/ops)→ 重建决策上下文;
  · 从"当前状态"继续决策(不做历史重放):PENDING 继续分、MIGRATING 读 handover 到期继续判、
    DRAINING 继续推进;
  · 业务层/执行器全程无感(归属键没变的照跑)。
```

### 4.3 全集群重启

```
前提:整个 ns 全部实例同时重启(如机房级维护)
行为:
  · 实例陆续注册 → 选主 → 主读全量;
  · 各实例对账:归属=我的 → 起线程;无归属的 PENDING → 主重新分配;
  · 最终收敛到"etcd 里的持久状态 + 本轮重新分配"。
注意:全集群重启时所有分区都经历一次"执行器重建",起点恢复策略(组位点/精确 seek)
    决定数据面是否无损——这是执行器契约的必答题(见接入设计子文档)。
```

## 五、与存量控制面的对应(消费底座)

| 框架阶段 | 原控制面对应物 | 说明 |
|---|---|---|
| ② 任务创建 | TaskRecord 创建 + onCreated | 批打底决策留外壳,不进入框架 |
| ③ 调度决策 | handover 的"授租约+下发" | 被框架归属分配取代 |
| ④ 执行 | UnitRunner 循环 | 收编为 spi 执行器,起点注入保留 |
| ⑦ 故障迁移 | Supervisor 租约巡检 + 重下发 | 被"判死双窗口 + CAS 改归属"取代 |
| ⑧ 注销 | 单元回收 | 被 DRAINING 流程取代(epoch 重规划驱动) |
