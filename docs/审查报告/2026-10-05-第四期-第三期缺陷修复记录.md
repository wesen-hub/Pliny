## 关键实现细节

### 高危-1 TSO 单位(T0Selector)
- 修复前 `gc + gcSafeMarginMs` 把毫秒当 TSO 直接相加,120000ms 余量实际只有 0.46ms;
- TiDbGcSafePoint 的 TSO 口径为 `ms << 18`,T0Selector 新增同口径常量;
- 离线自检 `T0GcMarginSelfCheck`(10 断言):换算精确性 / margin=0 边界 / 余量窗口抬升 / 不误触 R3。

### 中危-3 permitAll 收窄(关键口径)
- `/api/ingest/{logicalTable}`(POST)与 `/api/ingest/meta/{logicalTable}`(GET)是业务系统
  提交通道,appKey 自校验(Bearer appKey),**必须保持匿名可达**;
- 故不能一刀切 `anyRequest().authenticated()`,改为:
  ```java
  .requestMatchers(HttpMethod.POST, "/api/ingest/*").permitAll()
  .requestMatchers(HttpMethod.GET, "/api/ingest/meta/*").permitAll()
  ```
- 管理端点 `/api/ingest/apps/**` 自此走 JWT + @PreAuthorize。

### 中危-4 RestClient 超时
- JdkClientHttpRequestFactory(Spring 6.1)无 setConnectTimeout;
- 连接超时通过 JDK HttpClient 构造传入:
  ```java
  HttpClient client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build();
  JdkClientHttpRequestFactory f = new JdkClientHttpRequestFactory(client);
  f.setReadTimeout(Duration.ofSeconds(15));
  ```

### 低危-5 watch 续传(EtcdStore.ResumableWatch)
- 对调用方透明:onNext 记录 header revision;onError/onCompleted 后 1s 退避,
  从 lastRevision+1 重建;`rebuilding` 标志防双重建;主动 close 不重建;
- CompactedException 时回退为不带 revision 监听(与旧行为一致,靠周期对账兜底);
- 补齐 Watch.Watcher 接口的 requestProgress()/isClosed() 委托。
