## 三、关键场景验证路径与证据链

### 3.1 场景①:杀 master → watchdog 自动 restore 位点续采(H14 修正后的 PASS)

1. 三机 SeaTunnel 引擎集群重启(Mac 先独立成 master 再依次 join,规避 RM 懒初始化死锁);
2. kill 集群主节点 → Hazelcast 约 1s 选新主,但 RUNNING job 消失(实证了「master 宕机 job 不自动恢复」,推翻设计假设);
3. 修正后由控制面兜底:约 104s 后 backend 输出 `CDC job 丢失, 自动 restore`(阿里云 backend-2 持 ShedLock);
4. 引擎从周期 checkpoint 79(CHECKPOINT_TYPE)恢复 `isRestored=true`,`SnapshotSplitAssigner remaining tables: []` 无快照重做;同 jobId + isStartWithSavePoint=true;
5. **Kafka 证据**:位点 10210953(恢复点)→ 11755203(row-h)→ 12468275(row-i)严格推进;seq 36007 → 37001 → 37002 单调不回退。

### 3.2 场景②:删 checkpoint → restore 失败 → 回退 initial 全量重采(H10/H17 PASS)

1. 删 MinIO checkpoint 后 stop-job;
2. 约 111s 内 watchdog(腾讯云 backend-3 持 ShedLock)检出 `status=CANCELED` → 以 isStartWithSavePoint 提交;
3. 引擎 savepoint guard 补丁抛错 HTTP 400(报错文本原样入 backend 日志);
4. backend 输出 `restore 失败(无可用 savepoint?), 回退 initial 全量重采` → 新 jobId=179104984001801(旧 179102675125301)+ isStartWithSavePoint=false;
5. **Kafka 证据**:收 9 行全量(row-a..row-i 各 1 条不重不漏),seq 38001-38009 单调、`__src_pos` 全 `mysql::0:`(确证 initial 而非续采);新 job checkpoint 已重新落盘 MinIO。

### 3.3 H16 提交入口 failover 路径

- 缺陷:`hazelcast-client.yaml` cluster-members 默认仅 `localhost:5801` → 本机节点宕机则提交即断(集群活着但无人可提交);
- 修正:客户端成员列表改三节点(mac.wg + 10.66.0.2 + 10.66.0.3:5801);
- 实证:kill Mac 后云机提交成功——先试 mac.wg 被拒(Connection refused)→ 自动 failover 本地引擎 → 集群 Members [2]。

### 3.4 HA 验收后的腾讯云减负(环境演变)

- 前提:「HA 已验证后减负」;
- 动作:停 backend-3/seatunnel-3/mysql-slave/deliv-2/tag-2/sentinel-3 共 6 容器;
- 效果:used 6890M→4362M,available 394M→2922M;引擎降为 2 节点后 `runningJobs=1` 无中断(watchdemo 分区重分配);
- 保留:quorum/副本类(kafka-3/etcd-3/tikv-3/pd-3/nacos-3)与分布式 MinIO(minio-3b/minio-4,erasure coding 4 盘集群)不动。

### 3.5 Mac 休眠事故(H4/H5 真实实证,用户拍板定论)

- 现象:Mac 休眠 12h → PD 时钟冻结 → TiDB `TIDB_CURRENT_TSO()` 返回 0 → TiCDC(阿里)卡死(8300 API 无响应)→ 水位表冻结 → 批 T0 落在 GC safe point 边界 → 快照 `AS OF TIMESTAMP` 报「GC life time is shorter than transaction duration」,批失败;
- 处置:重启 pd-1、tidb-server、ticdc;TSO/水位恢复后重做批成功;
- 定论:① PD 三副本具备 HA 能力,节点宕机秒级切换且不回拨,本次故障是客户端连接未重建+隧道延迟,非 TSO 服务丢失;② 本环境 TiKV 仅 2 副本,失去一臂即 Raft 多数缺失、数据面停摆,TSO failover 无效;③ 部署缺口是缺 tikv-3 与 TiDB 多实例,而非 PD;④ 开发机应禁用休眠或不承载数据面。
