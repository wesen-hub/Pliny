# 代码服务清单（全模块）

> 微服务拆分(方案 N9-N12)完成后的代码模块全景。口径：**独立容器部署 = 一个部署实例**；库/内核模块被加载或依赖，不独立部署。
> 设计背景见同目录 [微服务架构方案.md](微服务架构方案.md)。

## 一、控制面应用服务（6 个，Spring Boot 独立部署，接入 Nacos）

| # | 模块目录 | 入口类 | 职责 | 关键内部组件 |
|---|---|---|---|---|
| 1 | `backend/` | `DataCollectPlatformApplication` | 平台主后端：数据源/建模/订阅/打标/资产/变更流出口的**统一控制面**，同步链路、湖批、文件同步、调度管理 | ShedLock 9 把域级锁；`ChangeOutletService`(批快照源)；`OutletPermissionEngine`(契约∩主体)；`SeaTunnelClient`(采集) |
| 2 | `outlet-service/` | `OutletServiceApplication` | 出口/消费底座**业务外壳**：对账、Supervisor 巡检、批交接、TaskScheduler 编排 | 依赖 `outlet-control`(决策内核) + `outlet-adapters`(IO 适配)；`BatchJobStore`(batch_job 判据) |
| 3 | `subscription-service/` | `SubscriptionServiceApplication` | 数据订阅域(方案 N11)：契约管理 + PULL 数据服务(schema/snapshot/changes/export) + push 定时投递 | 管理面走 JWT+@perm.isAdmin；订阅方 PULL 走 X-Dcp-Token 自校验 permitAll；ShedLock subTaskReconcile |
| 4 | `tagengine-service/` | `TagEngineServiceApplication` | 打标引擎域(方案 N9)：规则/任务/数据集/标签/在线/流作业/数据权限管理面 | `OnlineTagService`(读 Redis `tag:online:{entity}`)；`perm/DataSecurityService`(数据权限)；`TagV2Deployer`/`StreamJobService` 直连 outlet-service REST；ShedLock tagTaskReconcile |
| 5 | `asset-service/` | `AssetServiceApplication` | 资产目录+血缘域(方案 N12)：assetcat 人工业务打标/标签树 + lineage Neo4j 血缘图 | 血缘重建、目录查询均需登录 |
| 6 | `delivery-service/` | `DeliveryServiceApplication` | 出口交付域(方案 N10)：变更流出口 L3 六接口 + 批快照 + 消费方 SDK 运行时 + 契约视图 | `JdbcContractViewSource`(契约视图读元库)；出口栈指标(`module/outlet/metrics`)；`HttpOutletApi`(调 outlet-service) |

## 二、执行体池（1 个，一镜像一骨架多 ns）

| 模块目录 | 入口类 | 职责 |
|---|---|---|
| `dcp-worker/` | `WorkerApplication` | **统一调度框架执行体**（纯宿主）：内嵌 `dcp-scheduler-core`（分区调度/判死迁移/线程托管，基于 etcd）+ 按 ns 环境变量起 8 个池（sync/indexer/outlet/tag/lake/sub/ingest/filesync）；`WhitelistClassLoader`+`BundleAssembler` 加载业务 fat jar；`web/TasksController` 接收 TaskSpec 下发 |

## 三、独立作业（有 main，非服务；流批作业形态）

| 模块目录 | 主类 | 职责 |
|---|---|---|
| `dcp-tagstream/` | `StreamTagJob` | Flink 流打标：事件流 → Drools → 双写 Redis 在线层 + MySQL 投影层 |
| `tagengine-executor/` | `TagBatchJob` | Spark 批打标：批任务化执行（SmokeMain 本地冒烟） |
| `dcp-lakesync/` | `LakeSyncJob` | 湖批作业：数据下沉 Iceberg 湖表（LakeSyncSmokeMain 本地冒烟） |

## 四、采集 Agent（1 个，侧挂业务机，不注册 Nacos）

| 模块目录 | 入口类 | 职责 |
|---|---|---|
| `agent/` | `AgentMain` | 文件同步采集 Agent：长轮询拉任务 + rclone 推湖 S3；经网关连平台控制面 |

## 五、前端（2 个）

| 模块目录 | 技术栈 | 职责 |
|---|---|---|
| `frontend/` | Vue3 + Vite | 平台主前端：数据源/建模/资产/订阅/打标/出口等全部管理界面（nginx 静态 + 路径反代） |
| `scheduler-console/` | Vue3 + Vite | 调度控制台前端：分区调度/实例状态/任务大盘可视化 |

## 六、内核库（被加载或依赖，不独立部署）

| 模块目录 | 性质 | 职责 |
|---|---|---|
| `outlet-control/` | 纯逻辑内核（零第三方依赖） | 出口控制面决策内核：TaskScheduler/Supervisor/HandoverFacts 交接判据/批阶段规划；只做决策不做 IO，可离线自检 |
| `outlet-adapters/` | IO 适配层 | 决策内核的 IO 实现：`BatchJobStore`(batch_job 判据查询/回写)、契约视图 JDBC 源等 |
| `outlet-sdk/` | 消费方 SDK | 消费底座业务 jar 的开发契约（@ConsumerLogicDef 等） |
| `dcp-scheduler-core/` | 调度框架内核（shaded jar） | 基于 etcd 的通用分区调度与线程托管：TaskSpec/判死交接(AGGRESSIVE/CONSERVATIVE)/打分分配/四计数器快照 |
| `dcp-scheduler-api/` | 调度框架契约 | TaskSpec/ExecutorSnapshot/PartitionExecutor 等模型与接口 |
| `outlet-worker/` | 计算面单元运行器 | 消费底座单元内循环：CreateUnit → 加载 logic → assign+seek 起点 → 串行消费（被 dcp-worker 加载） |
| `dcp-outlet-rt/` | 出口执行体运行时(SPI) | 解码器/契约过滤(`ContractFilter`)/掩码(`Masker`)/死信(`DeadLetterSink`)/`PartitionTaskExecutor` |
| `dcp-indexer-rt/` | 索引器内核(SPI) | `AnchorIndexer` 栅栏锚点索引、CanalJson 解析、Poison 污染记录、`AnchorSamplerExecutor` |
| `dcp-filesync-rt/` | 文件同步内核(SPI) | `RcloneEngine`(rclone 无状态进程)、`RunRecorder`、`FilesyncExecutor` |
| `dcp-synclink/` | 同步链路任务内核 | `SyncConsumer` 消费信封流、`BatchWriteService` 批写、`AtomicUpsertDao` 原子 upsert、`DltService` 死信 |
| `dcp-tag-kie/` | Drools 规则内核 | 打标规则编译/执行（KieBuilder 静态编译，无运行时动态类） |

## 七、业务 fat jar（@ConsumerLogicDef，dcp-worker 加载执行，不独立部署）

| 模块目录 | 逻辑入口 | 职责 |
|---|---|---|
| `dcp-tag-task/` | `TagLogic`(tag-engine) | 打标批底座任务：按发布快照求值 → 双写 Redis 在线层 + MySQL 投影层(tag_fact_view/tag_notify) |
| `dcp-lake-task/` | `LakeLogic`(lake-sync) | 湖增量底座任务：消费 `dcp.{表}` 信封流 → seq 裁判/字段级合并 → Iceberg 湖表 overwrite |
| `dcp-ingest-task/` | `IngestLogic`(kafka-ingest) | 入站底座任务：消费 `dcp.in.{表}` → 验证/领号/打信封 → 发 `dcp.{表}` |
| `dcp-sub-push/` | `PushLogic`(sub-push) | 订阅推送底座任务：消费信封流/打标事件流 → 圈选/裁剪 → webhook/kafka 推送 |
