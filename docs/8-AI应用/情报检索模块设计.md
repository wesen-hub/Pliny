# 情报检索模块设计

> 状态:定稿(2026-10-12),汇总情报检索模块全部讨论定论(Agentic RAG/密级分区前置过滤/多轮编排/标签维度)。
> 定位:智能文档生成 Agent 的 L4 层——讲清「用了什么 RAG、怎么改造、检索返回什么、标签怎么进相关性」,是《智能文档生成Agent完整方案.md》的子文档。
> 配套:总体流程见《智能文档生成Agent完整方案.md》§四;chunk 模型见同文 §3.1;RAG 问答管线见既有 RAG 文档。

## 一、模块定位:Agentic RAG,不是纯 RAG

**直接结论:用了 RAG(混合检索),但有三处平台特化改造——密级分区前置过滤、Agent 多轮驱动、与结构化查询混合。** 标准 RAG 是「查询→召回→生成」单轮管线;本模块是「多轮检索编排」,由 Agent 决定「还要不要查、换什么词查」。

### RAG 在本系统的准确边界

| 环节 | 属于 RAG 吗 |
|---|---|
| 需求解析 + 硬校验 | ❌ |
| 多轮情报检索 | ⚠️ RAG 的「R」,但多轮决策驱动(Agentic RAG) |
| 大纲规划 | ❌ |
| 逐节整合(素材注入生成) | ✅ 此处用 RAG 技术 |
| 事实校验/密级合规 | ❌ |
| 模板交付/审计 | ❌ |

**结论:智能文档生成是 Agent 系统,内含 RAG 技术;RAG 是零件,Agent 是机器。**

## 二、模块内部结构(单次检索五段)

```
query(Agent 改写过的一轮检索意图)
  → ① 双路召回:向量路(embedding 语义)+ BM25 路(关键词精确匹配)
  → ② 前置硬过滤:密级分区 + 单位授权 + 时间窗(召回时同查执行)
  → ③ 融合:RRF(Reciprocal Rank Fusion)合并双路结果
  → ④ 排序:相似度 + 时间新鲜度 + 单位权重
  → ⑤ 返回 top-K chunks(带 numbers 预抽取清单 + 位置元数据)
```

### 为什么双路(向量+BM25)

- 情报查询常含**精确专名**(单位代号/装备型号/地名)——BM25 精确匹配强,向量语义弱;
- 语义模糊查询(「近期该区域活跃度」)——向量路优势;
- 两路融合:专名命中靠 BM25,语义扩展靠向量。

## 三、关键改造一:密级分区在召回时执行

Qdrant 按密级分区(payload 带 level + 查询时强制分区键):低密用户的查询在**向量计算前就把高密分区排除**——高密素材连「被算距离」的机会都没有。

与标准 RAG「召回后过滤」的本质区别:召回后过滤有旁路风险(过滤逻辑被绕过/遗漏);查询层分区是物理隔离,旁路不存在。**过滤顺序纪律:密级分区(安全闸)永远在标签过滤(相关性闸)之前。**

## 四、关键改造二:多轮检索编排

```
第 1 轮:主主题向量检索 → 召回素材集
Agent 评估覆盖率:时间窗有无空洞?子主题(需求解析时列出)有无缺项?
  → 有空洞 → Agent 改写查询(换关键词/扩时间窗/拆子主题)→ 第 2 轮
  → 收敛判定:连续 2 轮新增高相关素材 <前轮 20% → 停止
  → 轮数上限 5 → 强制停止
未达标部分 → 写 dataAsOf 声明(「10-02~10-04 情报缺失」),不允许静默带过
```

**Agent 在此只驱动检索方向,不生成内容**——这是 RAG 从「单轮工具」升级为「Agent 多轮决策」的分界。

### 覆盖率判定(建议值)

| 指标 | 建议值 |
|---|---|
| 时间窗覆盖 | ≥90% 的天至少 1 条素材(有情报流的天才统计) |
| 子主题召回 | 需求解析列出的关键子主题召回率 ≥85% |
| 检索收敛 | 连续 2 轮新增高相关素材(相似度 ≥0.75)数 < 前轮新增的 20% |
| 素材总量上限 | 单任务引用 ≤200 chunks |
| 轮数硬上限 | 5 轮 |

## 五、检索结果:原始文字,不是向量

向量库里每个 chunk 存两样东西:**vector(浮点数组,只用于算相似度)+ payload(原始文字与元数据)**。查询流程:

```
① 查询文字 → embedding 模型 → 查询向量(转一次,仅此一次)
② 查询向量在 HNSW 索引找最近邻 → 命中 point 的 ID + 分数
③ 返回命中 point 的 payload —— 原始文字 + 元数据
④ 向量使命结束;LLM 读到的只有文字
```

**检索结果未经大模型处理**(查询改写沾 LLM,但返回的 chunks 是库内原文)——这是「数字零幻觉」防线的底气:素材没被模型改写,校验器比对的是库内原始数字。

### 单轮检索返回结构

```json
{
  "query": "XX 区域本周兵力调动情况",
  "round": 2,
  "results": [
    {
      "chunkId": "c-9f3a", "fileId": "f-1002",
      "sourceUnit": "u-03", "securityLevel": 2,
      "eventTime": "2026-10-09T14:30:00Z",
      "position": {"page": 3, "offset": [1200, 1800]},
      "text": "10 月 9 日,XX 区域新增兵力约 1200 人,主要部署于……",
      "numbers": [{"value": "1200", "unit": "人", "confidence": "HIGH"}],
      "tags": [{"code": "troop-move", "path": "陆域/兵力调动", "depth": 2, "confidence": "HIGH"}],
      "score": 0.87
    }
  ],
  "coverage": {"timeWindow": [start, end], "coveredDays": 6, "totalDays": 7,
               "missingSubTopics": ["单位 u-05 动态"]}
}
```

四个关键属性分工:**text 喂模型;position 供引用溯源;numbers 供数字校验;securityLevel/sourceUnit/eventTime 供密级传导、单位归属、时间窗校验。**

## 六、三个情报来源分工(RAG 只是其一)

| 来源 | 技术 | 素材 | 角色 |
|---|---|---|---|
| 非结构化检索 | RAG(混合检索) | 报告/通报/图注/音视频转写 | 主体 |
| 结构化查询 | 直接查库(queryEventDb) | 事件表/单位档案/时间线 | 骨架(数字、时间线) |
| 用户显式指定 | attachMaterials | 用户点名的文件 | 补充 |

**数字优先走结构化来源**——事件表的数字是确定性事实,RAG 召回的数字过 numbers 预抽取校验;生成时按 dataSlots 分工:骨架数字查库,叙述性素材检索。

## 七、问答/生成共库的参数分化

情报库问答与生成共用(已拍板),检索模块同一套实现,参数分化:

| 维度 | 问答 | 生成 |
|---|---|---|
| 轮数 | 单轮 | 多轮(≤5) |
| top-K | 10 | 50/轮 |
| 过滤 | 密级/权限 | 密级/单位/时间窗/区域 |
| 返回 | chunk 列表 | chunk 集 + 覆盖率报告 |
| 延迟 | 秒级(专用快速队列) | 分钟级(批量队列,单任务 ≤2 QPS) |

## 八、标签维度设计(四层渐进 + 三路融合)

**术语纪律:情报标签叫「情报分类标签/主题标签」,不叫打标(平台定论:打标专指 Drools 规则打标)。**

### 标签树(taxonomy,深度 ≤3)

```
陆域 ── 兵力调动 ── 增援/撤防
海域 ── 舰艇活动 ── 编队/单舰
空域 ── 飞行活动 ── 侦察/巡逻
```

标签来源三路:解析时规则抽取(HIGH)/ LLM 标注(LOW,人工抽检升级)/ 人工标注(HIGH)。

### 参与相关性的四个层次(从弱到强)

| 层次 | 机制 | 效果 |
|---|---|---|
| ① 过滤维度 | 标签作硬过滤条件 | 标签是「闸」不是「分」 |
| ② 查询扩展 | 需求解析映射标签集,标签同义词进 BM25/向量 | 召回更全 |
| ③ 排序加权 | 标签重叠度计分,叠加融合分 | 同标签素材排名上升 |
| ④ 召回维度 | 标签倒排索引独立成路 | 语义模糊但领域精准的查询不漏 |

**关键判断:②③ 是标签最强作用,④ 后置**——标签质量不成熟时独立成路会放大错标;②③ 是加权纠偏,错标只影响部分排序。

### 三路融合公式

```
query → 标签意图 TagIntent{t1, t2, ...}(带层级,规则映射优先、LLM 兜底)

召回:向量路 top-50 + BM25 路 top-50 + 标签路(倒排精确匹配,可选)top-30

score = α·sim_vec + β·bm25 + γ·tagOverlap
tagOverlap = Σ 重叠标签权重(按 depth 递增,深层更具体)× confidence(HIGH=1.0, LOW=0.3)

三路 RRF 融合排名
```

层级距离加权:chunk 标签与 TagIntent 同子树(父子)给 0.5,完全同标签给 1.0。

### 落地时序(渐进)

| 阶段 | 内容 | 前置 |
|---|---|---|
| P1 | 标签只做过滤(用户手动筛) | 零风险,验证标签体系 |
| P2 | 查询扩展 + 排序加权 | 标签质量抽查通过 |
| P3 | 标签独立召回路 + 层级距离 | 标签覆盖率 ≥90% 素材有 HIGH 标签 |

### 四个坑与纪律

1. 错标放大:HIGH 错标 → 高权重 → 召回污染。LOW 标签不参与加权、人工抽检闭环;
2. 标签树失控:深度 ≤3、总量控制、每季度收敛评审;
3. 冷启动:三步渐进,不一步到位;
4. 过滤顺序:密级分区永远在标签过滤之前。

**底线:向量+BM25 主路永兜底,标签是「纠偏」不是「替代」——标签路挂了检索照样工作。**

## 九、面试口径(一句话版)

> 情报检索 = 「双路召回 + 召回时密级分区过滤 + RRF 融合 + Agent 多轮迭代 + 标签渐进加权」的 Agentic RAG——用了 RAG 技术,但密级安全、覆盖率判定、多来源分工、标签纠偏四层特化让它和教科书 RAG 拉开距离:标准 RAG 回答「有没有」,情报检索回答「覆盖够不够、缺了什么、数字可不可信」。
