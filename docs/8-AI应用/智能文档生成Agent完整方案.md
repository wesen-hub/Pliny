# 智能文档生成 Agent 完整方案

> 状态:定稿(2026-10-12),汇总智能文档生成 Agent 全部讨论定论(六层架构/六步流程/三类工具/四道防线/四拍板)。
> 定位:基于平台情报库的「需求驱动文档生成」Agent 完整方案——架构、领域模型、执行流程、工具体系、核心机制、Agent 关注点、接口与落地路线。
> 配套:平台级 Agent 架构铁律见《7-微服务架构/微服务治理架构与落地细节.md》同体系;RAG 管线见既有 RAG 文档;调度框架批量任务通道见《5-统一调度框架/》。

## 一、方案定位与边界

**定位**:各单位情报入湖,用户一句话提需求,Agent 检索、规划、逐节整合、校验、按模板交付情报报告。

**范围**:三模板并存(专题整合 / 周报 / 事件复盘);情报检索 + 报告生成两域。

**四条铁律**(设计基线,违反即设计错误):

1. **数字零幻觉**:情报数字只允许从素材搬运,禁止 LLM 自由生成;
2. **密级向下兼容**:任何环节满足「用户密级 ≥ 素材密级」,违反 = 拒绝,不是警告;
3. **强制溯源**:每段落挂出处(来源单位/文件/时间/位置),无出处段落不允许存在;
4. **LLM 不进正确性关键路径**:校验、密级判定、渲染全是确定性程序。

## 二、总体架构(六层)

```
L1 情报资产化   各单位文件 → 带元数据情报条目(来源单位/密级/事件时间/地理/模态)
L2 解析分块     模态特化(文本/OCR/ASR/抽帧)+ chunk 带位置 + numbers 数字预抽取
L3 索引存储     MongoDB(解析产物)+ Qdrant(向量,按密级分区)——问答与生成共用
L4 情报检索     混合检索(向量+BM25)+ 密级/单位/时间窗硬过滤(查询层分区)
L5 整合生成     docgen-agent:规划层(ReAct)+ 流水线(逐节/校验/合规)
L6 交付审计     模板渲染 → MinIO 版本化 → 全链路审计留痕
```

**服务划分**:一个 `docgen-agent` 独立服务(内网,LLM 私有化部署),进程内模块:规划器 / 工具层 / 校验器 / 审计器。异步批任务形态(长文档不进请求-响应链路),复用调度框架一次性任务通道。**LLM 挂了只影响生成功能,情报入湖与检索不受影响(降级无关)。**

## 三、领域模型

### 3.1 情报素材(Chunk)

```json
{
  "chunkId": "uuid", "fileId": "情报文件ID",
  "sourceUnit": "单位编码", "securityLevel": 3,
  "eventTime": "2026-10-08T10:00:00Z", "geoRegion": "区域编码",
  "modality": "text|image|audio|video",
  "position": {"page": 3, "offset": [1200, 1800]},
  "text": "解析文本(Markdown 表整体保护)",
  "numbers": [{"value": "1200", "unit": "人", "confidence": "HIGH|LOW"}]
}
```

`numbers` 预抽取(规则引擎主、覆盖常见模式 ≥95%、HIGH 置信;LLM 兜底中文大写/隐含表达、LOW 置信)——幻觉防线前移到数据生产环节。

### 3.2 生成任务(DocGenTask 状态机)

```
PARSING → RETRIEVING → OUTLINE_CONFIRMED → WRITING → VALIDATING
  → DELIVERED | REJECTED
(任意态可中断续跑,从已确认大纲的下一节继续)
```

### 3.3 大纲(Outline,先确认后生成)

```json
{
  "docTitle": "XX 区域一周态势整合报告",
  "dataAsOf": "截至 2026-10-11 18:00;10-02~10-04 情报缺失",
  "sections": [
    {"id": "s1", "title": "本周综述", "materialRefs": [{"chunkId": "...", "role": "主素材"}],
     "dataSlots": [{"key": "总事件数", "from": "structured"}]}
  ]
}
```

大纲 = 章节树 + 素材引用 + 数据槽位——**不是自由文本**,校验器可提前审计「素材密级是否超标、数字槽位是否有结构化来源」。

### 3.4 模板(TemplateSpec,骨架锁定)

| 模板 | 骨架 |
|---|---|
| 专题整合 | 背景 → 总体态势 → 分单位动态 → 研判 → 附件 |
| 周报 | 本周综述 → 分单位 → 趋势对比 → 下周关注 |
| 事件复盘 | 事件经过 → 时间线 → 原因研判 → 处置与建议 |

模板走 MinIO 版本管理;LLM 在骨架内规划章节,不能发明模板外章节(校验器做模板骨架比对)。

## 四、执行流程(六步,含失败路径)

| 步 | 输入 → 输出 | 确认点/失败路径 |
|---|---|---|
| ① 需求解析 | 自然语言 → Requirement 结构化 | 硬校验:超密级/越单位 → **直接拒绝**(程序行为,LLM 无裁决权) |
| ② 情报检索(多轮) | Requirement → 素材集+覆盖率报告 | 轮数 ≤5;收敛判定:连续 2 轮新增高相关素材 <前轮 20% |
| ③ 大纲规划 | 素材集+TemplateSpec → Outline JSON | **用户确认**(关键确认点) |
| ④ 逐节整合 | Outline+素材 → 章节文本(带引用) | 每节过校验器,BLOCK 重生成该节 ≤2 次,再不过转人工 |
| ⑤ 整体校验 | 全文 → 校验报告 | 数字/出处/密级三检,BLOCK 打回 |
| ⑥ 交付审计 | 校验通过文本 → 报告+审计记录 | 模板渲染 → MinIO → 归档留痕 |

## 五、工具体系(三类,暴露面不同)

### A 类:LLM 自主调用(READ 查询,暴露给模型)

| 工具 | 签名 | 封装能力 |
|---|---|---|
| `searchIntelligence` | (query, filters{levels/units/timeWindow}, topK) → chunk[] | Qdrant 混合检索(密级分区前置过滤) |
| `queryEventDb` | (eventType, timeRange, unitIds, limit) → row[] | 结构化情报库 |
| `queryRelation` | (entityId, depth) → 子图 | Neo4j |
| `attachMaterials` | (fileIds[]) → chunk[] | 用户指定素材 |

### B 类:流水线固定环节(确定性程序,绝不暴露给 LLM)

`validateSection`(事实校验)/ `checkSecurityLevel`(密级)/ `renderReport`(渲染)/ `getTemplate`(模板)

### C 类:审批类

`archiveReport`(写 MinIO)——WRITE_APPROVAL,执行前生成审批单。

### 调用机制

**Spring AI Function Calling(不用 MCP)**:`@Tool` 注解定义 → 注册 ChatClient → ReAct 循环内 LLM 输出 tool_call → ToolRouter 路由(参数 Schema 校验 → 预算检查 → 超时控制 → 审计埋点)→ 结果回填 → 继续思考。工具设计五纪律:暴露面最小化(B 类永不进工具清单)、参数必有 schema、确定性反馈、调用全审计、预算与超时双层(单工具 5s/单任务 30 次)。

## 六、核心机制细节

### 6.1 数字零幻觉(三道防线)

① 注入优先:prompt 注入「可用数字表」(numbers HIGH 清单),指令「只允许使用表中数字」;② 确定性校验:文中每个数字必须匹配 numbers 清单,不匹配 BLOCK;③ 无出处拒绝:MISSING_CITATION → BLOCK。

### 6.2 密级合规

- 检索:Qdrant 按密级分区,高密素材低密用户**查询层物理不可见**(不是召回后过滤);
- 注入:素材装配前 PAP/PDP 硬过滤;
- 输出:段落密级 = 引用素材最高密级;文档密级 ≥ 段落密级;超用户密级 REJECT。

### 6.3 覆盖率判定(建议值)

时间窗 ≥90% 天有素材、子主题召回 ≥85%、总量 ≤200 chunks、轮数硬上限 5;**未达标写 dataAsOf 声明,不允许静默带过**。

### 6.4 死循环防护(四处上限)

检索 5 轮 / 节重生成 2 次 / 工具调用 30 次 / 任务超时 30min——每个循环都挂校验器当裁判(确定性反馈才收敛,LLM 自我评估不收敛)。

## 七、Agent 关注点

| 关注点 | 方案 |
|---|---|
| 记忆 | 短期 = Requirement+Outline+滚动摘要+已生成章节;长期 = 情报库本身(不建向量知识库) |
| 幻觉 | 三道防线 + numbers 预抽取(第零道) |
| 死循环 | 四处上限 + 确定性反馈 |
| 评估 | 离线金标准 20 组(结构完整性/事实准确性/引用有效性三标)+ 线上修订 diff 回流;换模型跑离线集不回退才放行 |
| 上下文/成本 | 逐节只注入本节素材+滚动摘要(≤500 token);公共模板缓存 |

## 八、接口清单(REST)

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/docgen/tasks` | POST | 创建任务(自然语言)→ taskId |
| `/api/docgen/tasks/{id}/outline` | GET/PUT | 查/确认大纲 |
| `/api/docgen/tasks/{id}` | GET | 状态机 + 节进度 |
| `/api/docgen/tasks/{id}/sections/{sid}` | PUT | 人工改写(落修订=负样本) |
| `/api/docgen/tasks/{id}/report` | GET | 下载(权限+密级校验) |
| `/api/docgen/tasks/{id}/audit` | GET | 审计记录(审计角色) |

## 九、落地路线

| 阶段 | 内容 |
|---|---|
| P0 | 情报入湖(复用解析管线)+ 密级元数据标准 + numbers 预抽取 + 检索硬过滤 |
| P1 | **单模板(专题整合)闭环**:六步流程 + 校验器 + 审计 |
| P2 | 多模板(周报/复盘)+ 多轮检索 Agent + 大纲确认点 |
| P3 | 批量任务(调度框架通道)+ 评估闭环 + 密级合规自动化 |

## 十、与平台复用清单

文件解析管线(情报入湖)→ Qdrant/MongoDB(情报库,问答共用)→ 权限体系(密级过滤)→ MinIO+sha256(报告与模板版本化)→ 调度框架(批量任务)→ Agent 基建(Spring AI + 审批通道)→ 审计体系。

## 十一、面试口径(一句话版)

> 智能文档生成 Agent = 六层架构(情报资产化到交付审计)、六步流程(需求解析到大纲确认到逐节校验)、三类工具(A 类检索暴露给 LLM、B 类校验渲染由流水线强制执行、C 类归档走审批)、四道防线(数字零幻觉/密级向下兼容/强制溯源/确定性裁判)——情报入湖复用平台管线,LLM 只在辅助面,裁判永远是确定性程序。
