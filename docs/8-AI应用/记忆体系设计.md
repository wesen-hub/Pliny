# 记忆体系设计

> 状态:定稿(2026-10-12),汇总 Agent 记忆体系全部讨论定论(三层模型/元记忆三表/修订记忆四层生效/快照语义)。
> 定位:智能文档生成 Agent 的记忆设计——记忆分几层、每层存哪、怎么记、怎么查、怎么生效,是《智能文档生成Agent完整方案.md》的子文档。
> 配套:检索模块(长期记忆的召回入口)见同目录《情报检索模块设计.md》。

## 一、三层模型

| 层 | 生命周期 | 载体 | 内容 |
|---|---|---|---|
| 短期工作记忆 | 单任务内 | MongoDB 任务状态机 | Requirement / Outline / 滚动摘要 / 已生成节 |
| 长期知识记忆 | 跨任务 | 情报库本身 | 情报素材 / 事件档案 / 单位档案 |
| 长期元记忆 | 跨任务 | 平台元库三张结构化表 | 用户偏好 / 修订记录 / 处置记录 |

**顶层定论:长期知识记忆 = 情报库本身,不建向量影子库、不做模型微调。** 元记忆(偏好/修订/处置)走结构化表,不走向量。

## 二、短期工作记忆(任务内)

```json
{
  "taskId": "t-1001",
  "requirement": {...},                        // 需求解析产物,全任务只读
  "outline": {"version": 3, "sections": [...]}, // 已确认大纲
  "rollingSummaries": [                        // 滚动摘要:已生成节的压缩
    {"sectionId": "s1", "summary": "本周共 12 起事件,海上 7 起……", "tokens": 80}
  ],
  "generatedSections": ["s1", "s2"],           // 已完成节引用
  "cursor": "s3"                               // 当前进度(中断续跑锚点)
}
```

五要素分工:Requirement 是不变约束、Outline 是确认过的路线、滚动摘要是已写内容的压缩、生成节是成果、cursor 是断点。

**两个核心机制**:

1. **持久化即记忆**:任务状态机落 MongoDB,任意时刻中断,重启从 cursor 续跑——记忆是持久状态,不是上下文残影;
2. **滚动摘要**:每节生成后产出该节摘要(≤100 token),下一节只注入前 N 节摘要而非全文——解决长文档上下文爆炸。

## 三、长期知识记忆:为什么不用向量库

**决策过程(四问,顺序固定)**:

| 问 | 本系统答案 | 结论 |
|---|---|---|
| ① 记忆内容有没有权威主数据源? | 有——情报库(采集平台每天入湖+密级治理+审计) | 有 → 不建记忆库,直接检索主数据源 |
| ② 访问模式是精确还是语义? | 元记忆是精确查询;知识是语义召回(检索模块已提供) | 精确 → 结构化表 |
| ③ 内容涉密/需合规治理吗? | 涉密 | 只能复用主数据源的治理,不复制拷贝 |
| ④ 更新频率与一致性要求? | 每天入湖,高频强一致 | 影子库要配套同步管线,成本陡增 |

**三个否决理由**:①双源真理论——影子库必然滞后于每天入湖的情报库,引用影子库 = 生成过期情报;②密级治理要重做一遍,漏一处 = 密级旁路;③多一条同步管线,违反减法纪律。

**类比**:情报库是档案馆,Agent 的「回忆」= 去档案馆查档案,而不是把档案抄一份放进自己笔记本;笔记本只记「档案馆怎么用」的笔记(元记忆)。

## 四、长期元记忆:三张表

元记忆定义:「关于系统怎么被使用」的数据——不含情报内容、不含生成内容,密级零风险,可放平台元库。

### 4.1 偏好记忆(user_preference)

| 字段 | 说明 |
|---|---|
| user_id + pref_type + pref_value | 主键(某人 + 偏好类型 + 具体值) |
| count | 使用次数(聚合计数,不存流水) |
| stat_json | 附加统计(如章节顺序权重) |

**怎么记录**:用户每次确认大纲时,找到(人+偏好)那行把 count 加一;行不存在则新建 count=1。只存一个数字,不存「第几次用了什么」的流水账。

**怎么查询、怎么生效**:用户下次建任务且没指定模板时,需求解析的「填默认值」环节查表取 count 最高项自动填上——实时生效于生成流程,不是 AI 猜的,是一次查表拿到的数字。

**类比**:电商「默认收货地址」——每次下单选什么地址就累计使用次数,下次下单自动填最常用的。

### 4.2 处置记忆(disposition_log)

| 字段 | 说明 |
|---|---|
| task_id / type / code / 时间 | 哪个任务 + REJECT/CLARIFY + 原因码 + 时间 |

**怎么记录**:拒绝或追问发生时,校验代码追加一行日志。

**怎么查询、怎么生效**:离线统计任务按 code 分组计数(如「WINDOW_ILLEGAL 18 次」),维护者发现高频原因反哺需求解析规则调优。**不参与生成,服务的是系统维护者**。

**类比**:客服「工单原因统计」——每次找人工记一个原因,月底数一遍发现「退款问题最多」→ 优化自助流程。

### 4.3 修订记忆(revision_log)

| 字段 | 说明 |
|---|---|
| task_id / section_id | 哪个任务哪一节 |
| 改前 / 改后 | 改动对比 |
| 归纳类型 | 数字修正 / 表述改写 / 结构调整(离线归纳) |

密级归属:diff 含任务上下文 → 挂任务审计链下,访问继承任务密级校验,不进共享偏好表。

## 五、修订记忆的四层生效体系

修订记录里有两类性质不同的东西,**必须先分流**:

| 类型 | 例子 | 性质 |
|---|---|---|
| 风格类修正 | 删「综上所述」开头、用精确数字不用「约」 | 用户的写作习惯,跨任务通用 |
| 内容类修正 | 85 辆改成 86 辆 | 那次素材的具体事实,只属于那个素材 |

**四层生效**:

| 层 | 修订类型 | 生效范围 | 生效时机 | 例子 |
|---|---|---|---|---|
| ① 任务内引用一致性 | 内容类 | 本任务其他节 | 保存时即时 | 第 3 节改 86 → 第 5 节同素材同数字自动同步 |
| ② 素材标注回写 | 内容类 | 该素材后续所有任务 | 确认后即时 | numbers 标注 85→86,以后引用同素材都拿 86 |
| ③ 偏好泛化 | 风格类 | 该用户后续所有任务 | 保存时即时 | 删「综上所述」→ 以后生成 prompt 注入该习惯,不再写 |
| ④ 评估题库 | 全部 | 未来模型升级 | 离线定时 | 编成金标准考题,换模型跑分对比 |

**①②③ 是「当前用户后续任务即时生效」,④ 是「未来模型考试」——并存不冲突。**

**内容类为什么不能泛化**:85→86 只说明那次素材里数字是 86;若系统总结成「数字要往大改」,下次任务会乱改数字——违反数字零幻觉铁律。内容类只走 ①②④,严禁走 ③。

## 六、金标准集(评估题库)

**定义**:「题目 + 标准答案」的集合,用于自动检验模型质量。一条题目长这样:

```
题目编号: G-0231
题目内容: 「根据下面这段素材,生成一周态势综述节」+ 当时的原始素材全文
标准答案: 人工改后/专家确认过的正确文本
评分维度: 数字一致 / 结构完整 / 引用有效
```

**一条修订记录的完整一生**(怎么生效的走查):

1. 10-10:模型生成第 3 节「约 85 辆」;
2. 张三对着素材手改成「86 辆」,保存;
3. 系统自动在修订表加一行(改前/改后);
4. 10-11 凌晨:定时任务把它编成考题(题目=当时素材+指令,标准答案=张三改后的文本),存入金标准集;
5. 12 月换新模型 V4:金标准集全部题目让 V4 跑一遍自动打分,总分不低于现用模型才允许替换上线。

**来源三处**:资深情报员编写 / 人工复核通过的任务 / 修订记录(模型实际犯过的错,专治薄弱点,价值最大)。

**类比**:驾校题库——教练纠正记录编成考题,换新教练带学员跑题库,成绩不比老教练差才录用。

## 七、任务素材快照(记忆一致性)

长任务执行期间(30 分钟),情报库可能入新素材。**任务启动时给素材打快照 taskMaterialSnapshot,执行全程只读快照**——保证同一篇报告内的数字、时间线、引用严格一致,不存在「前半篇旧数据后半篇新数据」。任务完成后报告标注 dataAsOf,用户可发起「刷新任务」基于新素材重跑。这是平台「快照批」概念在 Agent 侧的复刻:执行期与更新期隔离。

## 八、读写白名单(Agent 不自由读写记忆)

| 方向 | 白名单 | 内容 |
|---|---|---|
| 写(五事件) | 需求解析通过 / 大纲确认 / 节通过 / 人工改写 / 任务终态 | 流水线自动触发,不是 Agent 的写作权限 |
| 读(三窗口) | 需求解析 / 大纲规划 / 离线评估 | 固定环节的查表动作,不是 Agent 工具 |

**纪律:记忆读写不是 Agent 的工具,是流水线的固定动作**——Agent 能自由调用的只有检索类 READ 工具,记忆操作排除在外(否则「读记忆→写记忆」循环是死循环重灾区)。

## 九、上下文 vs 记忆的边界

| 维度 | 上下文(注入窗口) | 记忆(持久状态) |
|---|---|---|
| 生命周期 | 单次 LLM 调用 | 跨调用/跨任务 |
| 容量 | 受限(≤500 token 滚动摘要) | 不受限(库有多大记多大) |
| 内容 | 本节干活需要的 | 全任务/全历史 |
| 类比 | 工作台 | 仓库 |

**原则:窗口里只放本节需要的,持久层放全部;记忆的「想起」靠检索,不靠全量注入。**

## 十、纪律清单

1. 不建向量影子库、不微调模型参数当记忆(双源真理 + 密级旁路 + 同步成本);
2. 内容类修订严禁泛化为通用规则(幻觉源),只走任务内同步/源头回写/评估题库;
3. 风格类偏好可撤销(每条规则带来源,用户在偏好页可删);
4. 素材标注回写需确认(影响所有下游任务);
5. 元记忆零情报内容(放元库、免密级治理的前提);
6. 记忆读写白名单化,Agent 不自由读写;
7. 长任务必须快照,执行期与更新期隔离。

## 十一、面试口径(一句话版)

> 记忆体系 = 三层模型(短期工作记忆/长期情报库/长期元记忆)+ 三件套机制(滚动摘要控窗口、任务快照保一致、情报库检索当记忆)——长期知识记忆不建影子库,情报库本身就是记忆,决策靠「有无权威源/精确还是语义」四问;元记忆三张结构化表(偏好计数/处置日志/修订对比),修订记忆四层生效(任务内同步、源头回写、偏好泛化、评估题库),内容类不泛化是数字零幻觉的底线;记忆读写白名单化,LLM 只看工作台,仓库按需取用。
