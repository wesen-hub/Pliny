# 批流衔接定位机制:栅栏(Fence)方案设计

> 状态:设计稿(未实施)。适用形态:TiCDC 集群 + `enable-table-across-nodes = true` 的乱序部署。

**定位与核心问题。** 批流衔接要做的事只有一件:把批边界时点 T0 换算成"每个分区第一个 commitTs > T0 的 offset",使快照覆盖全部 ≤T0 的状态、增量从 >T0 的第一条变更接上,不重不丢。现行机制建立在"分区内 commitTs 单调"假设之上——稀疏锚点 + 二分 + 短扫,再以单调性守卫(出现回退即污点化)兜底。但当前部署是 TiCDC 集群且开启了 `enable-table-across-nodes`(单节点写入速率不足的既定选择),同一张表由多个 Capture 按 Region 分片并行投递到同一 topic,分区内 commitTs 乱序成为常态:分片进度差、并发投递抖动、重放与迁移、Region 分裂、客户端重试都会产生"offset 大而 commitTs 小"的消息。单调假设不再可保,守卫将长期污点化,起点计算长期落在全扫路径,并可能撞上扫描上限导致任务无法启动。本方案用"栅栏索引 + 出口过滤"替代"单调假设 + 短扫降级":**起点只需保证"不漏"(安全下界),精确边界交给出口持续过滤**——在不对乱序幅度做任何假设的前提下恢复精确定位,把乱序从正确性问题降级为效率问题。

## 一、核心定义与定理

**栅栏点(Fence Point)。** 消息 F 是栅栏点,当且仅当"位置在 F 之前的所有消息,commitTs ≤ commitTs(F)"。

**等价于刷新点。** "F 之前所有消息的 commitTs ≤ commitTs(F)" ⟺ "commitTs(F) ≥ F 之前的历史最大 commitTs"。即:**栅栏点就是历史最大值刷新点**。索引器为观测乱序本就维护着历史最大,因此栅栏是零成本"免费产生"的,只需判定与采样入库。

**定理(不漏)。** 取"commitTs ≤ T0 的最大栅栏点 F",从 F 的位置开始消费,不会漏掉任何 commitTs > T0 的消息。

> 证明:设 A 为位置序第一条 commitTs > T0 的消息。反证:若 A 位于 F 之前,由栅栏性质有 commitTs(A) ≤ commitTs(F);由选点条件有 commitTs(F) ≤ T0;于是 commitTs(A) ≤ T0,与 A 的定义矛盾。故 A 必在 F 之后,从 F 起顺序消费必然覆盖 A。∎

**推论。** 证明只使用了"栅栏点自身的性质"与"选点条件",不依赖单调性、不依赖乱序幅度、不依赖分片结构与重试行为——**任意乱序下均成立**。乱序只影响 F 到 A 的窗口大小(效率),不影响正确性。

**与水位机制的关系。** TiCDC 的 WATERMARK 语义是"≤ wm 的事件已全部到齐",证明的是"早段完备";栅栏证明的是"前缀上界"。两者方向相反、互补——水位用于声明"已消费完备",栅栏用于确定"消费起点安全"。

## 二、整体架构

```
索引器(常驻)                 交接(控制面)               出口(增量)             消费方
──────────────            ──────────────            ──────────────        ──────────
连续消费各分区流            每分区:                    从起点逐批扫描
判定刷新点 = 栅栏           查"ts ≤ T0 的最大栅栏 F"    持续丢弃 tso ≤ T0      幂等落库
稀疏采样入库                起点 = F.offset             产出 > T0 事件         吸收偶发重复
维护观测指标               (缺失 → earliest)          位点以"扫到哪"推进
解析失败 → 污染 + 告警      边界审计 → 播种 + 授租约
```

- **索引器(数据面观测者)**:常驻消费、只读业务流,产出物只有"栅栏稀疏索引"与观测指标;
- **交接(控制面)**:起点计算退化为一次纯索引查询(零 Kafka IO),附加边界审计后播种给增量通道;
- **出口(增量通道)**:扫描与过滤合并为一次读取,被过滤事件照常计入"扫过"区间;
- **消费方**:收到的事件全部 >T0,依赖既有幂等契约吸收残余偶发重复。

## 三、关键机制

### 3.1 栅栏采集(索引器侧)

1. 单线程、按 offset 顺序、**全量消费**,不跳过任何消息;
2. 每条数据事件与"该分区历史最大 commitTs(lastMax)"比较:`commitTs ≥ lastMax` 即为刷新点(栅栏),更新 lastMax 并进入采样候选;小于则丢弃,**永不入库**;
3. 采样只在刷新点中取:每 10s 窗口取**最后一个**刷新点;窗口内无刷新则空缺,**不伪造**;
4. 采样密度不影响正确性,只影响查询窗口大小(宁缺毋滥);
5. 解析失败(脏数据、异常)一律**污染该分区 lastMax 为 +∞ 并告警**——此后该分区不再产生新栅栏,查询自动退化为 fallback(宁慢勿错);
6. 判定必须保持单线程顺序,禁止并行化。

### 3.2 起点计算与审计(交接侧)

```java
// ① 查栅栏:纯索引查询(零 Kafka IO)
Anchor F = anchors.lastFenceAtOrBefore(topic, p, epoch, T0);
long from = (F != null)
    ? Math.max(F.offset(), reader.earliestOffset(topic, p))   // retention 规范化
    : reader.earliestOffset(topic, p);                        // fallback:永远安全

// ② 边界审计
//   F 存在且未被删 → 安全:F 自身 ts ≤ T0 即"边界未被越过"的证据
//   F 缺失/被删   → 读 logStart 首条:ts ≤ T0 → 安全;ts > T0 → 告警(可能越界或被删)

// ③ 产出起点(partition, from, source = FENCE | FALLBACK_EARLIEST),播种给增量通道并授租约
```

与旧交接的差异:不做短扫;`maxScanRows` / `StartTooOldException` 退役;不再因"窗口超限"触发重做批。审计不通过的处置二选一:告警放行(数据面尽力,推荐)或拒绝要求人工介入——避免旧机制"重做批换新 T0 → 窗口更远 → 死循环"的陷阱。

### 3.3 出口持续过滤(增量侧)

1. 从起点逐批扫描;逐条数据事件:`tso ≤ T0` → 丢弃(半开边界,等号归快照),`tso > T0` → 收集;
2. **过滤是会话级持续规则**:乱序迟到的小 tso 会在后续批次持续出现,必须一直生效,不能只在第一批执行;
3. 位点推进**以"扫到哪"为准**:被过滤事件也计入扫过区间——不卡死、不回退,可重放、可对账;
4. 过滤落点**唯一化**:只放在出口服务端的批次组装处,不下放给各消费方;且只作用于"带 commitTs 的数据事件",不影响水位字段与旁路消费者(索引器、血缘、打标读全量,不受会话过滤影响);
5. 水位口径:会话水位语义限定为"对 > boundary 的应发集合"(需在契约中声明);
6. DDL 事件:≤T0 的 DDL 效果已含在快照 schema 中,可丢;其判定口径与数据事件分开定义。

### 3.4 存储:锚点表

```sql
ALTER TABLE chg_anchor ADD COLUMN fence TINYINT NOT NULL DEFAULT 0;
KEY idx_fence_tso (topic, partition_, epoch, fence, commit_ts);
```

- 查询:同现有 `lastAtOrBefore`,仅追加 `fence = 1`;栅栏点 ts 与位置同序,"最大 ts"即"最靠后的安全点";
- 存储量:10s/分区 ≈ 8.6k 条/天,与现采样策略同量级;
- epoch:沿用现有代次隔离;栅栏性质是"物理前缀"性质,跨代仍成立,换代只可能影响密度。

### 3.5 示例:乱序流中的定位

| offset | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| commitTs | 80 | 90 | 85 | 100 | 95 | **110** | 101 | 120 |
| 性质 | 栅栏 | 栅栏 | — | 栅栏 | — | 栅栏 | — | 栅栏 |

T0 = 102。答案(位置序第一条 >102)= offset 6(110);栅栏查询 = offset 4(100);从 4 起扫:100 → 95 → **110 命中**,窗口 3 条,正确。

对照:若盲采样把 offset 7(101,非栅栏)记入普通锚点表,查询按"ts 最大"选到它,从 7 起扫直接命中 120——**110 被跳过,漏数**。栅栏方案中 offset 7 这类点永远进不了表。

### 3.6 与旧机制的变化对照

| 环节 | 旧(单调假设版) | 新(栅栏版) |
|---|---|---|
| 前提 | 分区内 commitTs 单调 | 无环境假设 |
| 锚点采集 | 盲采样(5000 条/10s) | 只采刷新点,采样免疫 |
| 违规处理 | 守卫 taint → 全扫降级 | 无此路径;守卫降级为观测指标 |
| 起点计算 | 锚点 + 短扫(≤20 万条,可能失败) | 纯索引查询,永不失败 |
| 精确边界 | 短扫定位"第一条 >T0" | 出口持续过滤(半开) |
| 读放大 | 短扫 + 消费 = 2× 窗口 | 1× 窗口(边读边跳) |
| 消费侧重复 | 全部依赖幂等吸收 | 结构性重复归零 + 幂等兜偶发 |

## 四、正确性:三保证 × 四契约

**三条保证:**

- **不漏(硬约束)**:栅栏定理 + 起点审计 + retention 规范化;
- **不多(软约束)**:出口持续过滤;残余偶发重复(消费端重投)由幂等吸收;
- **不失败**:一切异常退化为"窗口变大",最坏退化全扫,永不抛异常。

**四个契约(违反才出问题):**

| 契约 | 内容 | 破裂后果 |
|---|---|---|
| C1 索引器完备 | 宁多勿少;解析失败污染 + 告警;判定单线程顺序,不可并行化 | 假栅栏 → 静默漏数 |
| C2 口径一致 | 索引器 commitTs 与出口 tso 同一提取逻辑;上线前回放对账 | 系统性错位 → 漏或重 |
| C3 路径唯一 | tso → offset 的翻译只此一处;集成测试断言"起点 ≤ 答案" | 起点过晚 → 漏,过滤无法兜底 |
| P retention | 起点 max(F, logStart);F 缺失/被删时执行边界审计;T0 逼近保留期即告警 | 唯一不可自救的物理边界 |

**失效不对称性**(设计原则):漏 = 契约破损(必须用断言、告警、对账来守);重 = 过滤漏做或环境滞后(可观测、可吸收);慢 = 一切异常的安全兜底。"多算无害、少算致命"是索引器判定的第一原则。

**异常与兜底:**

| 异常 | 行为 | 结果 |
|---|---|---|
| 栅栏采样空洞 / 重放期无刷新 | 查不到 F → fallback earliest | 慢,不错 |
| F 被 retention 删 | 从 logStart 扫 + 审计 | 慢;审计暴露"可能越界" |
| T0 在未来 | 扫到尾部无产出 | 位点推到尾,等新数据 |
| 索引器解析失败 | lastMax 污染 + 告警 | 此后 fallback,不错 |
| epoch 换代 | 栅栏密度可能骤降 | 慢,不错 |
| 极端乱序(全递减) | 只有首条是栅栏 | 慢,不错 |
| 过滤漏路径 / 条件写反 | 落点唯一化 + 半开边界测试 | 漏做 = 重;写反 = 漏 |

## 五、验证方式

1. **离线断言**(内核纯函数):栅栏判定(刷新/非刷新/相等/首条)、查询选择(ts ≤ T0 的最大栅栏)、过滤半开边界(== T0 丢弃)、fallback 路径;
2. **回放对账**(C2):历史数据上逐条比对"索引器视图 commitTs"与"出口视图 tso",任何截断、转换或特殊事件取值差异即为不合格;
3. **乱序注入端到端**:构造快慢分片交错流(含重放段),验证"起点 ≤ 答案"断言成立、消费序列与快照严格拼接(不重不丢);同时用"盲采样对照"复现旧方案漏数,确认新方案规避;
4. **审计告警演练**:模拟 F 被删、T0 逼近保留期,验证告警与人工流程;
5. **指标巡检**:栅栏密度、采样空洞率、窗口大小(起点到第一条 >T0 的距离)分布、过滤条数。

## 一句话收口

**索引器只采"刷新历史最大"的栅栏点做安全起点,出口持续过滤 `≤T0` 锚定精确边界——不漏靠三个可自证的契约(索引器完备、口径一致、路径唯一),不多靠一行半开过滤,一切异常只退化为窗口变大;批流衔接从此不再依赖"分区内单调"的环境假设。**
