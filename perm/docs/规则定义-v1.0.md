# 统一数据权限框架 · 规则定义全集（v1.0）

> **文档定位**：本文档是《设计文档-v1.1.md》的可执行规则细则，覆盖 v1 全系统已定稿场景的所有规则，是技术实现与测试验收的唯一依据。
> **与 v1.1 的关系**：细则扩展；若发现矛盾，以设计文档 v1.1 为准并修正本文档。
> **规则编号体系**：`R-<域>-<序号>`，每条规则含四要素：规则内容 / 执行位置 / 适用场景 / 违反处理。

---

## 1. 场景总览（v1 全系统支持场景）

### 1.1 已定稿场景（S1 ~ S7）

| 编号 | 场景 | 访问形态 | 支持引擎 | 核心规则组 |
|---|---|---|---|---|
| S1 | 交互式同步查询 | MyBatis / JDBC 接入，每次查询判定 | MySQL / TiDB / Doris / Trino | R-D、R-B、R-S、R-K |
| S2 | 批作业 / 流作业 | 提交时判定一次，快照语义 + HMAC 验签 | Spark / Flink | R-J、R-Sec |
| S3 | 数据导出 | `export.csv` 等动作，同 S1 链路 + 限流义务 | 同 S1 | R-D、R-A、R-O |
| S4 | 标签圈选与下钻 | `tag.claim` / `tag.drill`，三层机制 | TiDB（tag_fact_view）/ 业务引擎 | R-T、R-D |
| S5 | 图查询（血缘） | Cypher 命名参数 | Neo4j | R-G3 |
| S6 | 无绑定引擎访问 | 安全字面量转义 / JSON 结构化 | ES / MongoDB | R-B2、R-G4 |
| S7 | residual 兜底执行 | 谓词无法下推时 PEP 内存过滤 | 任意（有性能风险） | R-R |

### 1.2 预留场景（v2，v1 明确不支持）

订阅 PULL 通道、API 网关接入、多租户隔离、管理面 simulate/explain 仿真、灰度发布、模式 A 实体列表展开（默认禁用，见 R-T5）。

## 2. 判定规则（R-D）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-D1 | 策略匹配条件：subject ∧ resource ∧ action ∧ env ∧ effectivePeriod 全部满足才算匹配 | PDP 判定 Step1 | 未命中该策略 |
| R-D2 | DENY-overrides：任一 DENY 策略匹配 → 整体 DENY，绝对优先，不看 priority；否则任一 GRANT → PERMIT | PDP 判定 Step2 | — |
| R-D3 | 无任何策略匹配 → DENY（fail-closed） | PDP 判定 Step2 | — |
| R-D4 | priority 不参与 DENY vs GRANT 裁决；仅用于多 DENY 时选择 denyReason（取 priority 最高者） | PDP | 错用 priority 裁决 = 设计错误 |
| R-D5 | specificity（资源 > 主体 > 环境）**已删除**——交集合并语义下无消费方 | — | 禁止实现 |
| R-D6 | DENY 策略的 constraints 字段**忽略**（DENY = 无条件整体拒绝）；"减列/减行"在 GRANT 策略内用 excludeColumns / 谓词表达 | PDP | 若 DENY 带约束生效 = 越权风险 |
| R-D7 | 行谓词合并：所有 GRANT 策略非空 rowExpr 做 AND 连接（交集收窄）；某策略为空跳过；全空 → 无行级约束；变量保持符号形式 | PDP 判定 Step4 | — |
| R-D8 | 列合并：visibleColumns 交集（空则跳过）→ 减去全部 excludeColumns 并集 → 结果为空 EMPTY_SET | PDP 判定 Step4 | EMPTY_SET → PEP 拒绝 |
| R-D9 | 掩码最严优先：`FULL > NULL > HASH > PARTIAL > REPLACE`；**"未提及 ≠ 放行"**（任一策略掩码即掩码，无"显式明文放行"）；FULL 掩码列强制从 visible 剔除 | PDP 判定 Step4 | 掩码序可配置（裁决 F），默认固定 |
| R-D10 | 掩码列被查询谓词引用 → fail-closed；检测在 **PEP**（解析原始 SQL 时检查 WHERE / GROUP BY / ORDER BY / JOIN ON） | PEP ColumnMaskApplier / PredicateInjector | 拒绝查询 |
| R-D11 | 短路顺序：①策略匹配 → ②表级可见性 HIDDEN → ③动作权限（无 GRANT 允许该 action；`read.*` 通配，`*` 不跨段）→ ④标签门槛 | PDP 判定 Step3 | 任一步不通过 → DENY |
| R-D12 | 环境条件不满足**非短路**：该策略不适用，继续匹配其他策略 | PDP | — |
| R-D13 | 表级可见性来源优先级：用户级策略 → 角色级策略 → 资源密级兜底 → 默认 VISIBLE | PDP | — |
| R-D14 | 跨属性引用：多策略引用不同属性来源（subject/env/resource）→ AND 连接；语义不等则正常返回空结果，不报错 | PDP 判定 Step4 | — |
| R-D15 | 变量解析分工：PDP 编译期校验 ref 存在性与类型（失败 fail-closed）；**值**由 PEP 绑定环节解析（失败 fail-closed） | PDP / PEP | 拒绝 |
| R-D16 | 义务合并：并集 + 同类型取最强（AUDIT 取最高级别 detail > basic；RATE_LIMIT 取 min(maxRows)） | PDP 判定 Step5 | — |
| R-D17 | resourceType 显式枚举 TABLE / TAG（v2 扩展 FILE/API/TOPIC）；locator 按类型解释：TABLE 三段式 ns.db.table（段内 * 通配仅匹配不裁决）、TAG 标签路径 v1 精确匹配（前缀通配预留） | PDP 判定 Step1 | 未知类型 → 编译失败 |

## 3. 表达式规则（R-E）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-E1 | AST 节点全集：AND/OR/NOT、EQ/NE/GT/GE/LT/LE、IN/BETWEEN/IS_NULL/LIKE、FUNCTION_CALL、FIELD_REF / VARIABLE_REF / LITERAL / TAG_REF、CUSTOM | PDP 编译 | 未知节点 → 编译失败 |
| R-E2 | 变量命名空间：`${subject.*}`（主体属性）、`${env.*}`（环境）、`${resource.*}`（资源）；合法命名空间白名单校验 | PDP 编译 | 非法命名空间 → fail-closed |
| R-E3 | 类型系统：varchar / int / decimal / datetime / boolean；编译期做类型检查 | PDP 编译 | 类型不匹配 → 编译失败 |
| R-E4 | 函数白名单：v1 仅内置安全函数集；未白名单函数 → 编译失败；扩展走 CUSTOM 表达式 + 自定义实现 | PDP 编译 | 拒绝编译 |
| R-E5 | 等级体系三分离，禁止混用数字方向：SENSITIVITY L0~L4（越大越敏感）/ 表级可见性枚举 VISIBLE·HIDDEN·CONDITIONAL / tagLevel T0~T3（越大权限越强） | 全局约定 | 混用 = 语义错误 |
| R-E6 | TAG_REF 目标键可配置：`tagTarget = { kind: entity\|row, keyColumn, factTable }`；展开键不写死为 entity | PDP 翻译 | — |
| R-E7 | 表达式为引擎无关语义模型；任何方言特征不得进入表达式 | PDP | 方言泄漏 → 跨引擎失效 |

## 4. 编译与翻译规则（R-C）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-C1 | 按需编译：不做全组合预编译（避免笛卡尔积爆炸），缓存命中免编译 | PDP | — |
| R-C2 | 三层编译缓存：AST 缓存（键 policyId:version）/ 方言产物缓存（键 policyId:version:dialect）/ Plan 缓存（五元键 hash(planVersion, resourceId, action, rolesFingerprint, stableAttrFingerprint) = 产物键 − dialect；判定匹配条件含 resource/action，Plan 键必须含这两个维度）；分层键（C21）：域内存在 user/group 型策略时 Plan/产物键追加 subjectIdsFingerprint = hash(userId, sorted(groups))；策略变更时失效 | PDP | — |
| R-C3 | 方言渲染走 DialectRenderer SPI，粒度：ExprVisitor / FunctionMapper / IdentifierQuoter / TypeConverter / LiteralRenderer / PlaceholderRenderer | PDP | — |
| R-C4 | 无法下推的谓词回退为 residual AST（引擎无关），保证跨方言统一 | PDP | — |
| R-C5 | 产物模板化：placeholders 只含 {index, ref, type}，**绝无值**；bindOrder（含值）只存在于 BoundArtifact，不进缓存不出 PDP | PDP | 值进产物 = 违反 C1 |
| R-C6 | 产物有效期：`effectiveExpiry = min(L1 TTL, meta.expiresAt, 版本失效时间)` | PDP/PEP | 过期产物拒绝使用 |
| R-C7 | 动态 env（时间窗口等）在判定期**折叠进 decision**，不进缓存指纹；Plan 缓存 TTL 必须小于时间窗口粒度或边界对齐 | PDP | 过期缓存复用 = 越权 |

## 5. 缓存规则（R-K）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-K1 | 产物缓存键六元组：`hash(planVersion, dialect, resourceId, action, rolesFingerprint, stableAttrFingerprint)`；Plan 缓存键 = 产物键 − dialect（五元，见 R-C2）；分层键：域内存在 user/group 型策略时追加 subjectIdsFingerprint = hash(userId, sorted(groups))（Plan 五元→六元、产物六元→七元，见 R-C2）；指纹定义：rolesFingerprint = hash(排序后角色集合)、stableAttrFingerprint = hash(按名排序的 k=v 拼接，入选标准低基数/慢变/非 PII)；hash 作索引 + fullKey 二次校验 | PDP | — |
| R-K2 | stableAttr 入选标准：低基数、慢变、非 PII（如数据域）；波动属性一律走模板占位 + PEP 绑定 | PDP | 波动属性进指纹 = 缓存爆炸 |
| R-K3 | 存储结构：hash 作索引，条目为 `CacheEntry{fullKey, artifact}`；**命中后 fullKey 二次校验**，碰撞视为未命中 | L1/L2 | — |
| R-K4 | 三级缓存：L1 Caffeine 5 万 / L2 Redis 100 万 / L3 perm-service 全量 | — | — |
| R-K5 | 失效三通道：事件失效（<1s，收到即本地失效）为主；版本比对（5s 后台定时 + L2 比对，不做每请求比对）；TTL（30s ± 5s 抖动）仅自然过期 | PDP | — |
| R-K6 | 降级只收窄：PDP 不可达 → 缓存 PERMIT **立即降级 DENY**、DENY 保持、未命中 DENY；**不依赖 TTL 续用** | PDP | TTL 续用 = 收紧越权窗口 |
| R-K7 | 并发控制：击穿 → SingleFlight；雪崩 → TTL 抖动；穿透 → 缓存空结果（DENY）；失效风暴 → 延迟失效 + 分批预热 + 只失效收窄；Herds → 熔断 + 降级 | L1/L2 | — |
| R-K8 | DENY 结果同样缓存（防穿透），TTL 短于 PERMIT 可接受但必须有 | L1/L2 | — |

## 6. 绑定与注入规则（R-B）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-B1 | 参数绑定矩阵：A 类可绑定（MySQL/TiDB/Doris；Trino JDBC `?` + setXxx；Spark/Flink 视接入方式——JDBC 可绑定、SQL 文本执行需转义）→ `?` + 绑定；B 类无绑定（ES/MongoDB）→ 安全字面量转义；C 类部分支持 → 降级安全字面量转义。**总原则：优先参数绑定** | PEP ParamBinder | 有绑定能力却内联 = 注入风险 |
| R-B2 | 安全字面量转义细则：字符串 `'`→`''`、`\`→`\\`、控制字符转义；数值 BigDecimal.toPlainString；日期时间规范化格式；ES term query 为 JSON 结构化无需转义，wildcard/regexp 需转义 `* ?` 与正则元字符 | PEP | — |
| R-B3 | 绑定顺序契约：权限 `?` 位于原 SQL 所有 `?` 之后，bindOrder 按下发顺序逐位绑定 | PEP | 顺序错位 = 数据错乱 |
| R-B4 | Cypher 使用命名参数 `$name`；Neo4jExecutor 负责 bindOrder（位置语义）→ 命名参数 map 转换；**禁止内联字面量** | PEP | — |
| R-B5 | 注入位置：权限谓词注入在原 WHERE 之后（AND 连接）；无 WHERE 时补 WHERE | PEP PredicateInjector | — |
| R-B6 | 别名规范：单表查询以表名/别名限定列，避免歧义；注入谓词列引用与产物 columnProjection 一致 | PEP | — |
| R-B7 | MyBatis 细则：①拦截点 StatementHandler.prepare，经 SystemMetaObject 取 delegate.configuration（**BoundSql 上无 configuration 字段**）；②ParameterMapping 追加到 parameterMappings 末尾，值入 additionalParameters；③MyBatis CacheKey 在 Executor.query 阶段基于原始 SQL 计算（早于改写）→ **禁用二级缓存 + local-cache-scope: statement**，否则同 SqlSession 内跨权限上下文串数据；④插件顺序由 InterceptorChain 注册顺序决定，**@Order 无效**，自动配置显式排序；⑤PageHelper count SQL 是聚合查询会被 R-S2 误杀 → **豁免**（仅注入行谓词，不做列裁剪/掩码检查） | PEP | — |
| R-B8 | SQL 解析缓存：MyBatis 用 BoundSql.getSql() 直接作缓存键（命中率 ~100%）；JDBC 裸文本字面量归一化（`'...'`→`?`、数字→`?`）后作模板键；JSqlParser 无 clone API → 命中缓存后自建 AST 深拷贝（deparse+reparse 或 AST 复制器），避免改写污染缓存 | PEP | 污染缓存 = 跨请求谓词串扰 |

## 7. v1 SQL 范围规则（R-S）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-S1 | 支持清单：单表 SELECT、简单 WHERE（AND/OR/比较/IN/LIKE/BETWEEN/IS NULL）、显式列清单、单表 ORDER BY、单表 LIMIT、`SELECT *` | PEP QueryParser | — |
| R-S2 | fail-closed 清单：JOIN、子查询、聚合（COUNT/SUM/GROUP BY/HAVING）、UNION、CTE、窗口函数 → 报错 `UnsupportedSqlException: 当前查询包含不支持的特性：[JOIN]。请拆分为单表查询，或联系管理员配置自定义 Renderer。` | PEP | 拒绝查询 |
| R-S3 | 范围检查**只针对原始业务 SQL**；权限谓词由 PDP 生成、视为可信、豁免检查（含标签模式 B 注入的 IN (SELECT ...)） | PEP | — |
| R-S4 | SELECT * 展开：PEP 用 pushdown.tableSchema 展开 `*` → visibleColumns 交集 → 掩码列替换表达式；schema 来源优先级：产物携带（推荐）→ 本地缓存（定期同步）→ information_schema 实时查 | PEP ColumnPruner | schema 缺失 → 拒绝 |
| R-S5 | 掩码列被 WHERE / GROUP BY / ORDER BY / JOIN ON 引用 → 拒绝（同 R-D10） | PEP | 拒绝 |

## 8. 标签权限规则（R-T）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-T1 | 三层机制叠加：①准入判定（标签门槛短路，非谓词）②数据范围（TAG_REF → 谓词下推）③兜底（residual 内存过滤） | PDP/PEP | — |
| R-T2 | tagLevel 门槛映射：tag.read / tag.count 需 T1+；tag.claim 需 T2+；tag.drill 需 T3+；用户 tagLevel 来源同一 Policy 模型（action 命名空间 tag.*），用户级 → 角色级 → 标签继承逐级解析，默认 T0 | PDP 判定（R-D11 第④步） | 不足 → DENY |
| R-T3 | 两种权限语义：语义 1 约束标签维度（tag_path 白名单谓词：`AND tag_path IN (?,...)`，白名单为慢变权限数据）；语义 2 约束实体/数据行维度（TAG_REF 展开） | PDP | 混淆语义 = 约束错误维度 |
| R-T4 | 打标对象三形态：①实体标签 → 展开到业务表外键（`customer_id IN (...)`）②行级标签 → 展开到行主键（`id IN (...)`，事实表 row_tag_fact）③列内标签 → 不走 TAG_REF，直接行谓词（`tags CONTAINS '...'`）；**跨库约束下：形态①②的展开查询发生在标签服务内部（同库下推，见 R-T11），源库侧仅接收展开结果（实体列表）或授权声明** | PDP | — |
| R-T5 | 展开方式（跨库定稿，模式 B 已删除）：**模式 A 实体列表（`IN (?,...)`，实体数 < 1000）= 唯一 SQL 下推路径**——实体列表是值非表引用，跨库无影响；**校验式（实体数 ≥ 1000）= 大标签主路径**——不注入标签谓词，权限锚定在圈选动作（R-T2 门槛 + 授权校验 + sync 审计 + 审计后置离线比对越界）；模式 A 产物必带 snapshotVersion + 短 TTL（与标签服务快照对齐） | PDP 翻译 | 大标签硬走 IN 下推 = 参数上限/产物体积爆炸 |
| R-T6 | 快照语义：模式 A 产物**必带** tagScope.snapshotVersion + 短 TTL 与标签服务快照对齐，并显式声明成员变更延迟可见上限；**实体列表是唯一允许"值进产物"的例外**；snapshotVersion 由标签服务生成（成员变更时 +1），模式 A 产物 TTL = min(30s, 快照对齐 TTL) | PDP | 缺 snapshotVersion = 快照越权窗口不可收敛 |
| R-T7 | tagScope 产物字段：`tagPath / level / canDrillDown / expandMode / snapshotVersion / targetKey / factTable`；expandMode 枚举（跨库定稿）：`list`（模式 A 实体列表下推）/ `verify`（校验式，大标签圈选授权声明）——subquery 已删除 | PDP | — |
| R-T8 | 标签服务接口：getEntities(tagPath)（模式 A 展开，**响应必带 snapshotVersion**）/ getUserTagLevels(userId, tagPaths)（R-T2 门槛）/ batchCheckMembers(entityIds, tagPath)（residual 路径批量成员判定，预留）；服务不可用 → PDP fail-closed（默认），或显式配置"短缓存续用"降级（须声明快照版本）；成员查询 PDP 侧短缓存仅限模式 A，键含 tagPath + snapshotVersion | PDP | — |
| R-T9 | 语义 1 白名单谓词生成（跨库定稿：防线前移到标签服务内部）：PDP 解析用户有权标签列表 → `tag_path IN (?,...)`；标签服务内嵌 PEP（同库接入），查自己库表时白名单谓词正常 SQL 下推；白名单为慢变权限数据，无成员动态性问题 | PDP | — |
| R-T10 | 标签路径匹配语义：resourceId 为标签路径时 v1 精确匹配；前缀通配（如 `业务域/风控/*`）v2 预留，由 TAG 型 matcher 定义 | PDP | — |
| R-T11 | 标签服务接入规范（跨库三层防线）：①标签服务内嵌 PEP（与普通业务接入一致：引依赖 + Provider + 资源注册 + 策略）；②标签库表注册为资源（tag_def/tag_member 等），查自己库 = 同库查询 → 白名单谓词 SQL 下推（语义 1 落地位置）；③圈选/下钻 API 出口做动作授权（tag.claim 需 T2+ / tag.drill 需 T3+，R-T2 门槛 + 白名单校验 + sync 审计）；④所有圈选 API 响应必带 snapshotVersion（下游模式 A 快照对齐的契约）；⑤源库侧跨库不变：模式 A 列表下推 / 校验式（见 R-T5） | 标签服务 PEP | 圈选响应缺 snapshotVersion = 下游快照越权窗口失控 |

## 9. residual 规则（R-R）

| 编号 | 规则 | 位置 | 违反处理 |
|---|---|---|---|
| R-R1 | 触发条件：谓词无法下推到引擎（方言能力不足 / 自定义 Renderer 未实现该节点） | PDP 翻译 | — |
| R-R2 | 执行顺序（v1 修正版）：①pushdown 下推到引擎（含原 LIMIT）→ ②引擎执行 → ③residual 掩码（不影响行数，安全） | PEP ResidualProcessor | — |
| R-R3 | **residual 过滤的分页语义（修订版）**：PEP 检测 `residual.hasFilter() && 业务 LIMIT != null` → 摘除引擎 LIMIT/OFFSET，改为**过滤后分页**（PEP 在 residual 过滤完成后施加 LIMIT/OFFSET，见 R-R7）；仅当无法满足（深分页/无排序键/扫描超限）才 fail-closed 拒绝 | PEP | 引擎先 LIMIT 后过滤 = 语义错误（漏数据） |
| R-R4 | 结果集上限 10000 行，超限 fail-closed（防性能灾难） | PEP | 拒绝 |
| R-R5 | PEP 内置引擎无关 AST 求值器执行 residual 过滤与掩码 | PEP | — |
| R-R6 | 外部查询（residual.filters）批量请求，禁止逐行调用 | PEP | — |
| R-R7 | 后置分页语义（分页 = 过滤后分页）：①LIMIT/OFFSET 必须由 PEP 在 residual 过滤后施加；②结果集预计小（<10000）→ 去 LIMIT 全量拉回 → 过滤 → PEP 内存分页；③结果集大 → fetch-until-full 循环拉批凑页：确定性排序（ORDER BY 排序键在可见列内，缺失 → 拒绝）+ keyset 分页优先（`WHERE id > cursor ORDER BY id LIMIT batch`）+ PEP 侧批次缓存（过滤剩余行缓存供下页消费）+ 三重上限（累计扫描量 ≤ 10000 / 引擎往返 ≤ 20 批 / 批次缓存容量）；④后置分页审计：扫描行数/返回行数/页码/游标必记（防分页探测），深分页（OFFSET 超阈值）告警或拒绝 | PEP | 违反分页语义 = 页间漏数据/重复 |
| R-R8 | 实体列表分页（标签/实体级权限专用）：分页维度从业务行切换到权限实体——①实体列表在标签服务侧完成权限过滤 + 按 entity_id 确定性排序；②每页取 pageSize 个实体 → `entity IN (页内值)` 下推源库（每页纯值可下推，大集合逐页变小集合）；③页游标随查询上下文传递（RequestContext 携带 lastEntityId）；④标签服务提供按游标分页的实体接口 | PEP/标签服务 | 实体列表不排序 = 页间重复/遗漏 |

## 18. 策略配置参考（Policy DSL v1）

### 18.1 配置载体与完整模板

策略以 JSON 定义，经管理面 API（R-M5）提交，判定永远基于 PolicyVersion 不可变快照。字段全集如下：

```json
{
  "policyId": "pol_sales_region_001",
  "policyName": "区域经理-本区域订单可见",
  "version": 3,
  "priority": 100,
  "effect": "GRANT",

  "subject": {
    "type": "role",
    "ids": ["regional_manager"],
    "attributes": [
      { "ref": "${subject.level}", "op": "EQ", "value": "manager" }
    ]
  },

  "resource": {
    "resourceType": "TABLE",
    "resourceId": "sales_db.sales_order",
    "columns": ["order_id", "amount", "region", "status", "customer_phone"],
    "excludeColumns": ["customer_id_card"],
    "visibility": "CONDITIONAL"
  },

  "actions": ["read.snapshot", "read.changes", "export.csv"],

  "constraints": {
    "rowExpr": "region = ${subject.region} AND status IN ('paid', 'pending')",
    "maskRules": [
      { "column": "customer_phone", "rule": "PARTIAL",
        "expression": "CONCAT(LEFT(`customer_phone`,3),'****',RIGHT(`customer_phone`,4))" }
    ],
    "env": [
      { "ref": "${env.ipRange}", "op": "EQ", "value": "office" }
    ]
  },

  "obligations": [
    { "type": "AUDIT", "level": "detail", "sync": true },
    { "type": "RATE_LIMIT", "maxRows": 10000 }
  ],

  "effectivePeriod": {
    "from": "2026-09-01T00:00:00+08:00",
    "to": null
  },

  "meta": {
    "owner": "数据安全组",
    "description": "区域经理查看本区域订单"
  }
}
```

字段语义要点：
- `effect`：GRANT / DENY；DENY 策略 constraints 忽略（R-D6）
- `priority`：仅多 DENY 时选 denyReason（R-D4），不参与 GRANT vs DENY 裁决
- `subject.attributes`：主体属性收窄（与 ids OR 之后再做 AND 收窄）
- `resource.resourceId`：三段式 `ns.db.table`，通配 `*` 只用于匹配不用于裁决；标签资源直接写标签路径（见 18.4）
- `resource.columns`：可见列白名单；`excludeColumns`：排除列（减列语义，R-D8）
- `resource.visibility`：VISIBLE / HIDDEN / CONDITIONAL；优先级：用户级→角色级→资源密级兜底→默认 VISIBLE（R-D13）
- `actions`：分层命名空间；`read.*` 通配、`*` 不跨段；tag.read/count 需 T1+、tag.claim 需 T2+、tag.drill 需 T3+
- `constraints.rowExpr`：行谓词表达式（语法见 18.2）
- `constraints.maskRules`：FULL/NULL/HASH/PARTIAL/REPLACE，严格序合并（R-D9）
- `constraints.env`：环境条件，不满足→策略不适用（非短路，R-D12）
- `effectivePeriod`：时间窗口，策略匹配条件之一（R-D1）
- `obligations`：AUDIT（level basic/detail、sync true/false）/ RATE_LIMIT（maxRows）/ NOTIFY（预留）

### 18.2 rowExpr 表达式语法

| 元素 | 语法 | 说明 |
|---|---|---|
| 变量 | `${subject.region}` / `${env.ip}` / `${resource.*}` | PDP 校验存在性，PEP 绑定值（R-D15） |
| 字面量 | `'paid'` / `123` / `3.14` / `true` | 字符串单引号 |
| 比较 | `= != > >= < <=` | 数值/字符串 |
| 集合 | `IN / NOT IN / BETWEEN` | 值列表或子表达式 |
| 模糊/空 | `LIKE / IS NULL` | LIKE 通配 `% _` |
| 逻辑 | `AND / OR / NOT` | 组合 |
| 标签 | `TAG('业务域/风控/黑名单')` 或 `customer_id IN TAG('...')` | 展开规则见 R-T5/R-T6 |
| 自定义 | `CUSTOM('fnName', arg...)` | 走 CustomExpr SPI（R-E4） |

### 18.3 掩码类型

| 类型 | 语义 | 严格序 |
|---|---|---|
| FULL | 完全隐藏（列剔除，谓词引用即拒绝 R-D10） | 最严 |
| NULL | 置空 | |
| HASH | 哈希（SHA256） | |
| PARTIAL | 部分遮蔽（自定义表达式） | |
| REPLACE | 替换固定值 | 最宽 |

### 18.4 标签配置要点

- **语义 1（约束标签维度）**：策略 resource 直接指向标签资源（resourceId = 标签路径），actions 用 `tag.*` 表达门槛；判定通过后 PDP 生成 `tag_path IN (...)` 白名单谓词（R-T9）
- **语义 2（约束实体/行维度）**：rowExpr 中用 TAG_REF；resource 声明 `tagTarget = { kind: entity|row, keyColumn, factTable }`；默认模式 B 子查询展开，模式 A 默认禁用（裁决 C）
- **用户 tagLevel 来源**：由授予的 `tag.*` 动作推导；用户级 → 角色级 → 标签继承逐级解析，默认 T0（R-T2）

### 18.5 代表性示例

**示例 A：行级 + 掩码 + 列裁剪（区域经理）**——即 18.1 完整模板。判定效果：

```sql
-- 产物 pushdown（模板）
SELECT order_id, amount, region, status,
       CONCAT(LEFT(`customer_phone`,3),'****',RIGHT(`customer_phone`,4)) AS customer_phone
FROM sales_order
WHERE region = ? AND status IN ('paid','pending')
-- placeholders: [{index:0, ref:"subject.region", type:"varchar"}]
```

**示例 B：DENY 黑名单（用户封禁）**

```json
{
  "policyId": "pol_deny_user_007",
  "effect": "DENY",
  "priority": 999,
  "subject": { "type": "user", "ids": ["user_007"] },
  "resource": { "resourceId": "sales_db.*" },
  "actions": ["read.*", "export.*"],
  "constraints": {}
}
```

判定效果：user_007 对 sales_db 任何查询 → DENY（DENY-overrides，constraints 忽略）。

**示例 C：标签语义 2（黑名单客户的订单）**

```json
{
  "policyId": "pol_tag_blacklist_order",
  "effect": "GRANT",
  "subject": { "type": "role", "ids": ["risk_analyst"] },
  "resource": {
    "resourceId": "sales_db.sales_order",
    "tagTarget": { "kind": "entity", "keyColumn": "customer_id", "factTable": "tag_fact_view" }
  },
  "actions": ["read.snapshot", "tag.claim"],
  "constraints": {
    "rowExpr": "customer_id IN TAG('业务域/风控/黑名单')"
  }

```

判定效果（模式 B，默认）：

```sql
... WHERE customer_id IN (SELECT entity FROM tag_fact_view WHERE tag_path = ?)
-- placeholders: [{ref: "tagScope.tagPath", type: "varchar"}]
```

**示例 D：多策略叠加（双角色合并）**

用户同时命中两条 GRANT：

```json
// 策略1（销售角色）：rowExpr = "region = ${subject.region}"，掩码 customer_phone FULL
// 策略2（审计角色）：rowExpr = "status = 'paid'"，无掩码
```

合并结果（R-D7/R-D9）：

```sql
WHERE (region = ?) AND (status = 'paid')
-- customer_phone 掩码 FULL（最严优先，"未提及≠放行"），列从可见集剔除
```

### 18.6 多策略合并速查

| 维度 | 合并规则 |
|---|---|
| Effect | DENY-overrides（R-D2） |
| 行谓词 | AND 连接（R-D7） |
| 列 | 交集 - exclude 并集（R-D8） |
| 掩码 | 最严优先（R-D9） |
| 义务 | 并集 + 同类型取最强（R-D16） |
